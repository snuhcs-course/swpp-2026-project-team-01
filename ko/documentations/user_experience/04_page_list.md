# 페이지 목록

날짜: 2026-10-19
상태: 제안된 페이지 설계이며 구현 보고서가 아님
관련 문서: [프런트엔드 아키텍처](../technical_specification/02_frontend_architecture.md)

이 목록은 애플리케이션의 웹 화면을 정의합니다. [PRD](../02_product_requirements.md)는 릴리스 범위를, [채팅 워크스페이스 사양](../../openspec/specs/chat-workspaces/spec.md)은 합의된 대화 우선 동작을 소유합니다. 단일 호스트 채팅 페이지 `/app`과 요청자 경로 `/booking/[bookingId]`는 선택된 명명 방향이며, 아래 페이지 설계는 여전히 제안 상태입니다. 새로운 세부 동작은 구현 전에 OpenSpec 변경으로 정리해야 합니다.

아래 경로의 대상 오리진은 **`https://release.findmeatime.com`**입니다. 호스트 채팅은 `https://release.findmeatime.com/app`, 공개 호스트 페이지는 `https://release.findmeatime.com/{handle}`, 비공개 이어가기는 `https://release.findmeatime.com/booking/[bookingId]`입니다. 콜백과 링크 설정은 [배포 설정](../technical_specification/03_provider_setup.md#deployment-origin)을 참고하십시오.

## 내비게이션과 페이지 모델

맥락에 맞는 카드와 항상 닿을 수 있는 입력창을 갖춘 중앙 정렬 대화를 사용합니다. 간결한 메뉴가 호스트 채팅 안에서 설정, 요청 선택, 설정 컨트롤과 로그아웃을 엽니다. 고정 사이드바, 대시보드 지표, 별도의 일반 채팅 홈, 모델 선택기는 도입하지 않습니다. 세부 선호 수정은 [인터페이스 계약](03_interfaces.md)에 따라 같은 페이지 안의 라벨이 붙은 채팅 내 편집기에서 열리며, 취소하거나 저장하면 포커스가 복원됩니다.

공개 방문자는 `/` 또는 호스트의 `/{handle}` 링크로 진입합니다. 로그인한 호스트는 `/app`에서 자신의 에이전트와 대화합니다. 로그인 상태, 설정, 요청 검토, 설정 컨트롤은 모두 그 같은 페이지의 상태와 맥락 컨트롤입니다. 요청자는 제품 계정을 만들지 않고 비공개 요청 링크로 이어갑니다. 이메일과 iMessage 대화는 동일한 애플리케이션 레코드를 사용하며, 브라우저 동의나 검토가 필요할 때 이 페이지들로 연결됩니다.

| P09 | `/booking/[bookingId]` | 무작위 예약 링크가 요청자의 자격 증명이며, 검증된 연락처를 통해 링크 재전송 가능 | P08이 시작한 같은 게스트 스레드로, 새로고침이나 Google 복귀 후 저장된 이벤트에서 불러옵니다. 검토된 수정, 선택 사항인 캘린더 가용 시간, 후보 선택, 현재 제안 동의, 상태가 각각 스레드 안의 카드로 나타납니다. 검증된 연락처로의 접근 복구, 대안, 예약 시작 전 철회를 제공합니다. 이메일과 개인 에이전트 이어가기는 이곳으로 돌아오며, 확정 후에는 허용된 예약 영수증과 참여 링크를 표시합니다. 초안의 식별자를 여기서 열면 일반적인 이용 불가 화면을 보여 줍니다. |
| P10 | `/connect/authorize` | 인증된 호스트와 검증된 개인 에이전트 OAuth 인증 트랜잭션 | 클라이언트를 식별하고, 요청된 애플리케이션 권한을 보여 주며, 허용/거부를 받습니다. 로그인 과정에서도 트랜잭션 상태를 유지합니다. 이는 논리적 동의 화면이며 최종 OAuth 서버 라우팅은 백엔드 설계의 일부입니다. 캘린더 접근, 호스트 자격, 회의 승인은 부여하지 않습니다. |

`/app`은 호스트의 에이전트 채팅 페이지입니다. 별도의 접근, 설정, 받은 편지함, 요청 상세, 설정 페이지로 리디렉션하지 않습니다. 페이지 ID P04–P07은 의도적으로 사용하지 않으며, 그 책임은 P03에 속하고 요청자와 동의 ID는 그대로 유지됩니다.

- 설정을 마치기 전에는 예약 링크나 요청 컨트롤 대신 설정 화면을 표시합니다. 정지된 호스트는 비공개 에이전트 이력이나 호스트 작업 없이 중립적인 이용 불가 상태를 보며, 로그아웃과 제한적으로 허용된 권한 해지는 계속 사용할 수 있습니다.
- 설정 중에는 저장된 대화와 초안을 재개하며, 캘린더 연결/선택, 일정 규칙, 선택 사항인 iMessage 연동, 명시적 설정 검토가 포함됩니다. 예약/스킬 링크는 서버가 준비 상태를 확인한 후에만 표시합니다.
- 준비가 되면 호스트-에이전트 대화를 이어갑니다. 대기 중인 요청은 선택 가능한 카드 또는 검색/상태 필터, 비어 있음/로딩 상태, 전달 문제를 갖춘 맥락 선택기로 표시합니다. 요청을 선택하면 `/app` 안에서 허용된 논의와 현재 제안을 불러오며, `/app?request={requestId}`로 주소를 지정할 수 있습니다. 요청은 레이블이 붙은 전환 장치와 함께 열립니다. **Thyme과 비공개(Private with Thyme)**는 결정 카드가 있는 호스트 비공개 논의이고, **공유(Shared)**는 현재 제안과 상태를 함께 보여 주는 읽기 전용 요청자 대화이며 입력창이 없습니다([`host-review-and-booking` 설계](../../openspec/changes/host-review-and-booking/design.md#2-host-discussions-and-the-switch)).
- 제안을 검토하고, 승인하고, 변경을 요청하고, 거절하며, 비공개 규칙/이동 설명을 맥락 안에서 확인합니다. 각 동작은 해당 요청과 현재 제안 리비전을 명시합니다. 공유 논의와 비공개 논의는 한 번에 하나만 표시하며, 보이는 논의를 바꿔도 두 이력이 합쳐지지 않습니다.
- 정확한 규칙, 캘린더, 시간대, 개인 에이전트 권한을 위한 라벨이 붙은 페이지 내 대화상자를 엽니다. iMessage 연동은 인라인 대화 카드로 유지합니다. 모델 장애 중에도 이러한 컨트롤을 사용할 수 있게 하고, 닫은 뒤에는 포커스를 대화로 되돌립니다.

인증과 제공자 동의는 전용 경로를 사용할 수 있으며, 이후 `/app`으로 돌아와 서버가 승인한 맥락을 복원합니다. 알림 진입과 새로고침은 소유권을 확인한 뒤에만 의도한 요청을 복구해야 하며, 경로 자체는 요청 접근 권한을 부여하지 않습니다.

## 요청자 예약 목적지

`/[handle]`은 새 요청을 시작하는 공개 진입점으로, 게스트가 그곳에서 보낸 첫 메시지가 초안과 그 대화를 시작합니다. 게스트의 신원이 확인되면 `/booking/[bookingId]`가 바로 그 대화와 최종 영수증을 위한 안정적이고 보호된 목적지입니다. 이 페이지는 별도의 관리 대시보드를 도입하지 않고 대화 셸을 재사용합니다. 호스트는 `/app` 안에서 선택한 요청을 검토합니다.

여기서 `bookingId`는 접수 시점부터 사용자에게 보이는 일정 레코드를 식별합니다. 이는 서버 측에서 도메인 요청으로 해석되며, 이후의 캘린더 이벤트 ID나 예약 시도 ID가 아닙니다. 페이지 이름이 "booking"이라고 해서 이벤트가 존재한다는 뜻은 아닙니다. 조율/협상 중, 호스트 승인 대기, 예약 대기 또는 불확실, 확정, 또는 다른 종료 상태 등 권위 있는 수명 주기를 명시적으로 표시합니다.

요청자 확인 이메일의 **예약 보기(View booking)**도 같은 목적지를 사용합니다. `bookingId`는 서버가 생성한 무작위 UUID이며 요청자의 유일한 자격 증명입니다. 링크를 가진 사람이 그 요청을 가진 것입니다. UUID를 추측하는 것은 불가능하므로 보호의 초점은 유출 방지에 있습니다. 식별자는 참석자와 공유되는 캘린더 설명, 리퍼러, 검색 색인, 전체 요청 로그에 나타나지 않으며 해시로 저장됩니다. 종료 후 링크는 캘린더 이벤트 자체 외에 아무것도 담지 않은 최소한의 영수증만 보여 줍니다. 호스트는 인증된 호스트 워크스페이스를 통해 비공개 콘텐츠를 검토합니다.

공개 호스트 페이지와 예약 목적지의 이용 불가 화면은 라벨이 붙고 키보드로 조작할 수 있는 **내 예약 링크 다시 받기(Resend my booking link)** 컨트롤을 제공해야 합니다. 이메일 주소를 받고, 알 수 없는 요청, 검증되지 않은 요청, 종료된 요청, 전달 불확실성에 대해 동일한 일반 피드백을 보여 줍니다. 활성 요청의 이전에 검증된 현재 연락처만 현재 링크를 받으며, [재전송 계약](../../openspec/specs/meeting-requests/spec.md#requirement-accessible-link-resend)과 그 발급 횟수 제한을 따릅니다. 유출이 의심될 때 링크를 교체하는 기능은 초기 릴리스 범위 밖입니다. 재전송은 대화 런타임 복구와 별개이며, 동의, 승인, 예약을 만들지 않습니다.

종료 후에는 만료되지 않은 기존 요청자 자격 증명이 [회의 요청 계약](../../openspec/specs/meeting-requests/spec.md)에 따라 최소한의 종료 상태와 확정된 영수증만 허용합니다. URL이 안정적으로 유지된다고 해서 자격 증명의 수명이 연장되거나, 협상이 다시 열리거나, 과거 대화 기록이 노출되지는 않습니다. 영수증 내용과 동작은 [초대 설계](03_interfaces.md#booking-confirmation-email-and-calendar-invitation)를 따릅니다. 출시 전 재구축이므로 기존 요청자 경로에 대한 리디렉션은 필요하지 않습니다.

## 채팅 내 카드와 동작

이 이름들은 제품 컴포넌트를 설명하는 것이며 기존 프레임워크 API가 아닙니다. 카드는 검증된 애플리케이션 데이터와 허용된 동작을 받으며, 모델이 작성한 문장이 권한 있는 버튼을 만들 수는 없습니다.

게스트 페이지에서는 모든 카드가 대화 스레드 안에서, 그 카드를 불러온 어시스턴트 메시지나 도구 결과 뒤에 순서대로 놓이고 이력에 남습니다. 실행 가능한 카드는 최대 하나만 열려 있으며 현재 다음 단계의 카드로, 순서는 신원, 검토, Calendar, 후보 시간, 제안입니다. 다른 모든 카드는 제공되고 선택된 내용의 한 줄 영수증(변경이 허용되는 곳에는 **Change**), 자기 단계를 기다리는 상태, 또는 현재 카드로 가는 길이 있는 **Out of date** 표시입니다. 요청의 상태는 카드가 아니라 스레드 안의 한 줄입니다. 입력창만 스레드 아래에 있고 그 옆의 간결한 메뉴에 **Edit details**와 **Withdraw request**가 있으며, 폼, 패널, 카드는 그 바깥에 두지 않습니다([D13](../../openspec/changes/requester-intake-and-feasibility/proposal.md#decisions), [설계 12](../../openspec/changes/requester-intake-and-feasibility/design.md#12-requester-conversation)). 새 카드는 제목에 키보드 포커스를 받습니다.

| 카드 | 위치 | 동작과 결과 |
|---|---|---|
| 게스트 신원 | P08 스레드 | 어시스턴트가 이름과 이메일을 묻는 메시지(`ask_for_identity` 호출) 뒤에, 목적이 적용된 뒤에, 또는 단계가 제한된 작업(시간 찾기, 선택, 동의)이 신원이 필요하다고 답할 때, 또는 초안의 메시지 30개 한도에서 나타납니다. **Google로 계속(Continue with Google)**은 신원과 읽기 전용 캘린더 접근을 한 화면에서 요청하며, 또는 **Google 없이 계속(Continue without Google)**과 인라인 이름/이메일 입력(`request.identify`); Google에서 이름과 이메일 자동 입력(Google이 인증한 주소는 확인된 것으로 간주), 직접 입력한 주소에 대한 생성 이메일. 어느 쪽이든 초안이 수집 중으로 바뀌고 주소 표시줄이 P09로 제자리에서 바뀌며, Google 콜백은 P09의 같은 스레드로 돌아옵니다. 캘린더 부분을 거부해도 신원은 미리 채워지며, 로그인은 다른 요청에 대한 접근을 부여하지 않습니다. |

| 세부 정보 검토 | P08, P09 스레드 | `draft_request_review`가 작성한 어시스턴트 메시지 뒤에 나타납니다: **Apply these details**와 **Dismiss**가 있는 추출된 세부 정보, 또는 작성된 확인 질문. 요청이 초안인 동안에도 동작합니다. |
| 회의 세부 정보 | P09 스레드 | 스레드 메뉴나 카드의 **Edit details**, 또는 적용된 세부 정보의 **Change**로 엽니다: 목적, 소요 시간, 방식, 장소 또는 회의 링크, 가능한 시간, 이동 수단, **Save details**이며, 모델을 쓸 수 없는 동안에도 사용할 수 있습니다. |
| 연락처 확인(상태 줄) | P09 스레드 | 게스트의 신원이 확인된 곳의 한 줄: 예약 링크가 간 곳, **Send again**(60초 간격, 시간당 및 일일 한도) 또는 일치하는 경우의 **Use verified Google email**, 그리고 확인은 선택 사항이라는 안내; 동의 후에는 두 번째 줄이 요청이 호스트를 기다린다고 알려 줍니다. **Withdraw request**는 스레드 메뉴에 있습니다. 선택 사항이며 그 무엇도 이를 기다리지 않습니다. 전달 상태를 확인과 분리해 표시하고, 알 수 없는 동작은 같은 요청으로 복구하며, 확인 링크는 채팅 밖에 둡니다. 로그인이나 회의 승인은 부여되지 않습니다. |
| 요청자 링크 재전송 | 공개 호스트 페이지와 P09 이용 불가 화면 | 라벨이 붙은 이메일 입력란과 **내 예약 링크 다시 받기(Resend my booking link)**는 존재 여부, 연락처 상태, 전달 결과를 드러내지 않는 일반 피드백을 반환합니다. 현재 링크는 검증된 연락처로만 전송됩니다. 정확히 같은 재시도는 작업 식별을 유지합니다. 자격 증명 붙여넣기 입력란이나 로그인은 필요하지 않습니다. |
| 캘린더 연결 | P03, P09 | 로그인 동의에 캘린더 스코프가 포함되지 않았을 때의 **Google Calendar 연결(Connect Google Calendar)**, 재연결, 선택 사항인 경우 건너뛰기(**Skip for now**는 서버에 유지되므로 새로고침해도 다시 열리지 않으며, 그 영수증의 **Change**가 다시 제공함), 또는 연결 해제. 브라우저 동의는 같은 호스트 초안/요청으로 돌아오며, 서버가 검증한 뒤에만 연결됨으로 표시합니다. 요청자 접근은 가용 시간 확인으로만 한정됩니다. |
| 캘린더 선택 | P03; 요청자용 변형은 P09 | 실제 호스트 캘린더를 이유, 계정/접근 라벨, 수정 가능한 선택과 함께 추천하며, 충돌 확인과 쓰기 가능한 예약 대상을 구분합니다. 확인된 선택을 저장하면 공개된 첫 분석이 자동으로 시작되며, **다시 분석(Analyze again)**은 명시적인 새로 고침/복구 동작입니다. 요청자는 가용 시간 캘린더만 선택하며 호스트 설정 추론은 받지 않습니다. |
| 온보딩 제안 | P03 | 주간 미리보기의 비공개 캘린더 기반 회의 가능 시간대, 제안 상한이 포함된 주당 미팅 부하 카드, 확인하면 제외되는 메모성 이벤트 카드, 가장 빈번한 지역과 장소를 담은 방식/장소 카드를 각각 근거, 표본 수, 범위, 불확실성과 함께 제공합니다. **사용(Use)**, **조정(Adjust)**, **직접 선택(Choose my own)**, 또는 수동 설정은 초안만 변경합니다. 실패한 읽기나 추론된 장소를 확정된 선호로 제시하지 않습니다. |
| 설정 검토 | P03 | 제안된 설정과 누락된 값을 보여 주며, **설정 확인(Confirm settings)** 또는 **수정(Edit)**을 제공합니다. 입력한 선호는 조용히 저장된 정책이 아니라 초안을 만듭니다. |
| 채널 연동 | P03 | **iMessage 연결(Connect iMessage)**은 서비스의 iMessage 번호, 일회용 연결 코드, **코드 복사(Copy)**(정확한 메시지 문구를 복사), **메시지 앱 열기(Open Messages)**(수신자와 코드가 이미 입력된 상태로 메시지 앱을 여는 `sms:` 딥링크. 메시지 앱을 열 수 없는 곳에서는 붙여 넣을 수 있도록 번호와 코드를 계속 표시)를 담은 인라인 카드를 펼칩니다. 호스트의 메시지가 도착하면 카드는 마스킹된 발신자와 **확인 및 연결(Confirm and link)**을 보여 주고, 이어서 검증된 연결 상태를 표시합니다. **대신 코드 받기(Send me a code instead)**는 전화번호 입력, **코드 보내기(Send code)**, 보호된 코드 입력란, **확인 및 연동**으로 전환합니다. 적절한 경우 **나중에(Maybe later)**, 재시도/번호 변경, 연동 해제를 제공합니다. 마스킹된 발신자, 만료, 전달 상태, 재전송 제한을 표시합니다. 서버가 보낸 코드를 돌려주지 않으며, 입력한 코드를 대화 기록이나 모델 컨텍스트에 추가하지 않습니다. 설정 대화상자나 별도의 연동 페이지는 필요하지 않습니다. |
| 후보 시간 | P09 스레드; P03의 승인된 호스트 보기 | 날짜, 시간, 명명된 시간대, 회의 시간 길이, 방식/장소를 표시하며, **이 시간 선택(Choose this time)** 또는 대안 요청을 제공합니다. 선택은 예약이나 호스트 승인이 아닙니다. |
| 제안 검토 | P03, P09 | 정확한 공유 세부 정보와 리비전을 표시합니다. 요청자는 **이 제안에 동의(Agree to this proposal)**를, 호스트는 **이 제안 승인(Approve this proposal)**, **변경 요청(Request changes)**, **거절(Decline)**을 봅니다. **변경 요청(Request changes)**은 새로운 시간, 소요 시간, 방식, 장소 또는 링크의 제안을 엽니다. **제안된 공유 변경 검토(Review proposed shared changes)**는 현재 값과 제안된 값을 비교하며, **수정된 세부 정보 공유(Share revised details)**는 시간을 확인하고 요청자의 동의를 위한 다음 버전을 만들고, **제안 닫기(Dismiss suggestions)**도 제공합니다. 호스트 전용 예외는 비공개로 유지됩니다. 오래된 동작은 현재 제안으로 새로 고쳐집니다. |
| 규칙/이동 검토 | P03 | 비공개 제약, 이동 예상 시간, 여유 시간, 해결되지 않은 입력을 표시합니다. 수동 허용(**이 이동에 N분 허용(Allow N minutes for this trip)**)이나 주간 한도 면제(**주간 한도를 넘어 이 요청 허용(Allow this request beyond my weekly limit)**)를 명시적으로 확인하며, 필수 제약을 우회하는 기능은 절대 제공하지 않습니다. |
| 결정과 예약 상태 | P03, P09 | 동의/승인 대기, 예약 중, 불확실한 결과, 확정된 예약, 전달 실패를 구분합니다. 영수증은 확정된 캘린더 이벤트에 대해서만 나타나며, 유효한 온라인 회의 URL이 있으면 최종 세부 정보와 **회의 참여(Join meeting)**를 표시합니다. **예약 상태 확인(Check booking status)**은 상태를 새로 고치고, 쓰기가 불확실한 동안에는 또 다른 조정을 시작합니다. |
| 링크 공유 / 클라이언트 연결 | P03; 공개 인계는 P08 | 유효한 예약/스킬 링크를 복사하고, 승인된 개인 에이전트 연결을 확인하거나 해지합니다. 스킬 문서를 읽는 것만으로는 클라이언트가 연결되거나 승인되지 않습니다. |

제안된 호스트 iMessage 연동 흐름은 인증된 브라우저에 일회용 연결 코드를 보여 주고, 호스트가 자신의 iMessage에서 그 코드를 보내게 하며, 그 브라우저에서 마스킹된 발신자를 확인합니다. 서비스가 보낸 6자리 코드를 브라우저에 입력하는 방식은 대체 경로입니다. iMessage에서 먼저 시작한 소개는 인증된 브라우저 연동으로 이어질 수 있으나, 그것만으로는 비공개 접근 권한을 부여하지 않습니다. 구현, 실제 전달, 실제 Google/iPhone 인수 검증은 메인 스펙 승격 전에 아직 진행 전입니다.

## 지원 경로와 화면

| 화면 | 목적과 경계 |
|---|---|
| `/auth/callback` | 검증된 호스트 인증을 완료하고, 부여된 캘린더 스코프와 리프레시 토큰을 기록하며, 허용 목록에 있는 상대 경로 목적지로 리디렉션합니다. 유효하지 않거나 만료된 상태는 읽을 수 있는 로그인 오류로 돌려보냅니다. |
| `/auth/sign-in?consent=calendar` | 호스트의 이후 또는 갱신된 캘린더 동의입니다. `prompt=consent`와 `include_granted_scopes`를 사용하는 동일한 Google 로그인이며, 그 `/auth/callback`이 부여된 스코프와 리프레시 토큰을 기록하고 `/app`으로 돌아갑니다([`host-onboarding` 설계](../../openspec/changes/host-onboarding/design.md#7-google-calendar-client-and-renewed-consent)). 따라서 호스트에게는 별도의 콜백 라우트가 필요 없습니다. 요청자의 요청 바인딩 동의는 대신 `/connections/google/callback`을 사용합니다(다음 행). 검증되지 않은 쿼리 매개변수에서 행위자나 복귀 목적지를 도출하지 않습니다. |
| `/connections/google/start`, `/connections/google/callback` | 요청자의 **Continue with Google** 또는 **Connect Google Calendar**입니다. 호스트 로그인과 별개인 애플리케이션 소유의 Google 동의이며, 하나의 초안 또는 열린 요청(페이지가 그 예약 식별자를 가지고 있는 것)과 시작한 브라우저에 결합됩니다. 신원과 가용 시간 전용 캘린더 접근을 별도의 요청 결합 권한 부여로 기록하며, 초안의 경우 Google 이름과 이메일로 게스트의 신원도 확인합니다. 호스트 계정, Supabase 사용자, 세션을 만들지 않습니다. 같은 스레드로 돌아가며, 게스트의 신원이 확인된 뒤에는 예약 페이지로, 초안에서 동의를 취소한 뒤에는 `/{handle}`로 돌아갑니다. [`requester-intake-and-feasibility` 설계](../../openspec/changes/requester-intake-and-feasibility/design.md#3-requester-google-consent)에서 제안되었습니다. |
| 알 수 없거나 만료된 식별자를 가진 `/booking/[bookingId]` | 재전송 컨트롤이 있는 일반 이용 불가 화면을 보여 주며, 요청의 존재 여부는 드러내지 않습니다. [회의 요청 계약](../../openspec/specs/meeting-requests/spec.md)은 링크를 30일로 제한하고, 종료 시 변경/OAuth 권한을 제거하며, 링크가 유효한 동안 최소한의 종료 영수증 읽기만 허용합니다. |
| `/SKILL.md`, `/[handle]/SKILL.md` | 공개 에이전트 탐색 문서입니다. 공개 지침, 지원되는 연결 경로, 호스트 정보만 노출합니다. 이들은 리소스이며 채팅 페이지가 아닙니다. `/`와 `/[handle]` HTML 페이지가 이를 발견할 수 있게 합니다. 링크가 있는 페이지 내 에이전트 섹션, `<link rel="alternate" type="text/markdown">`, 루트 `llms.txt`, 그리고 같은 URL에 대한 `Accept: text/markdown` 요청에는 Markdown을 제공합니다. |
| 설정/선택 대화상자 | 호스트 규칙 수정과 캘린더 선택은 `/app` 안에서 열리며, iMessage 연동은 인라인 채팅 카드를 사용합니다. 닫을 때 대화를 보존하고 포커스를 복원합니다. |
| 권한 없음, 찾을 수 없음, 이용 불가 화면 | 보호된 요청 세부 정보를 노출하지 않습니다. 예약 목적지에서 식별자를 알 수 없거나 만료되었으면, 요청의 존재 여부를 드러내지 않고 동일한 일반 링크 재전송 컨트롤을 제공합니다. 토큰 붙여넣기 컨트롤은 없으며, 종료된 요청은 변경 권한을 되찾을 수 없습니다. |

공개 핸들을 해석하기 전에 `app`, `booking`, `auth`, `connect`, `connections`, `api`, `eve`, `SKILL.md`, `llms.txt`, 프레임워크 자산, 운영 경로를 예약해 둡니다. 제공자 웹훅, MCP 전송, OAuth 프로토콜 엔드포인트, 내부 에이전트 API는 내비게이션 페이지가 아니라 백엔드 엔드포인트입니다. 최종 배포 라우팅은 공개 핸들 경로가 이들을 가로채지 않도록 해야 합니다.

## 페이지 상태와 복구

- 보호된 모든 페이지는 로딩, 승인된 콘텐츠, 만료된 접근, 사용할 수 없는 데이터, 재시도 가능한 실패를 구분합니다. 인증이 완료되기 전에 캐시된 비공개 콘텐츠를 순간적으로 보여 주지 않습니다.
- P03은 로그인이나 동의 후 저장된 초안을 재개하며, 캘린더 거부와 선택 사항인 iMessage 실패가 준비 상태를 조작하거나 관련 없는 수정을 막지 않습니다.
- P09는 누락된 세부 정보와 일치하는 항목 없음을 명확화나 대안으로 해결합니다. 사용할 수 없는 캘린더는 빈 시간으로 취급하지 않습니다. 명시적인 시간대를 표시하고, 동의하기 전에 모호한 서머타임 시간을 해소합니다.
- P03/P09는 결정을 받아들이기 전에 오래된 제안을 새로 고칩니다. 수락된 수정은 오래된 결정 컨트롤을 지웁니다. 중복 클릭은 하나의 동작 식별을 재사용하며, 불확실한 요청 결과는 재시도 전에 상태 조회를 시작합니다.
- 예약 중에는 이벤트가 이미 존재할 수 있음을 표시합니다. 요청자의 철회가 이미 전송된 쓰기의 취소를 의미해서는 안 됩니다. 예약된 요청은 예약 후 변경을 위해 사용자에게 캘린더를 안내하며, 자동 일정 변경/취소는 범위 밖입니다.
- 모델/스트림 실패는 초안 텍스트, 확정된 메시지, 구조화된 동작을 보존합니다. 확인된 중단 대화는 **지금 다시 연결(Reconnect now)**과 별개로 **대화 복구(Recover conversation)**를 제공합니다. 복구는 현재 논의와 저장된 컨트롤을 유지하며, 회의를 승인하거나 추가 메시지를 만들지 않습니다. 불확실한 응답에는 **같은 복구 다시 시도(Retry same recovery)**와 **복구 상태 확인(Check recovery status)**을 제공합니다. 새로고침하면 권위 있는 상태를 확인하며, 수락된 대기 텍스트는 계속 읽을 수 있고 보내지 않은 초안은 컴포넌트 메모리에만 남습니다. 알 수 없는 상태와 소진된 허용량은 새 어시스턴트 입력을 계속할 수 없는 이유를 설명합니다. 알림 실패는 예약 실패와 구별됩니다.
- 대화 접근이 종료되면 보호된 이력과 컨트롤을 제거하되, 로컬에서 입력한 텍스트는 읽기 전용 **내 초안 텍스트(Your draft text)** 패널에 유지합니다. **초안 텍스트 선택(Select draft text)**과 **초안 삭제(Discard draft)**를 제공하며, 이 텍스트가 이 페이지에서만 유지된다는 점과 불확실한 전송은 다시 보내기 전에 확인해야 한다는 점을 설명합니다.
- 휴대폰과 200% 확대에서도 동작과 입력창에 닿을 수 있게 유지합니다. 눈에 보이는 포커스, 의미 있는 라벨, 키보드로 조작 가능한 메뉴/대화상자, 복원되는 포커스, 절제된 라이브 안내, 색상 외의 상태 텍스트를 사용합니다.

## 범위와 인수 매핑

| 페이지 | 제품 범위 | 핵심 확인 사항 |
|---|---|---|
| P01–P03 | FR-01–04, FR-33, FR-35 | 개방형 호스트 로그인, 중단된 설정, 명시적 설정 검토, 해지된 캘린더, 준비된 경우에만 링크 표시 |
| P08–P09 | FR-05–15, FR-19, FR-23, FR-32, FR-34, FR-36 | 계정 없는 접근, 범위가 제한된 이어가기, 명확화, 가용 시간/개인정보, 현재 동의, 철회, 승인된 최종 영수증 |
| P03 | FR-16–23, FR-27–28 | 비공개/공유 분리, 정확한 제안에 대한 결정, 오래된/동시 동작, 불확실한 예약, 채널 복구 |
| P03, P10 | FR-24–26, FR-29–31 | 검증된 채널/클라이언트 연동, 구분된 권한, 해지, 브라우저 동의 |
| 모든 대화형 페이지 | 채팅 워크스페이스 사양; PRD 개인정보/신뢰성 | 키보드/모바일 접근, 인증, 새로고침, 재연결, 모델 장애, 사용자 간 비공개 캐시 없음 |

요청자 이메일과 호스트 iMessage는 필수 채널이며, 어느 쪽도 범용 메시징 받은 편지함 페이지를 요구하지 않습니다. MCP, CLI, 명시된 개인 에이전트와의 호환성은 이 페이지 목록 밖의 릴리스 요구사항으로 남으며, 연결/해지 화면은 여기에 포함되어 있습니다. 비공개 호스트 이메일은 제안된 확장으로 남으며 추가된 범위가 아닙니다. 운영자의 정지, 복원, 진단은 관리자 CLI를 사용하며 이 설계에서 새로운 공개 관리자 대시보드를 필요로 하지 않습니다.
