# Find Me a Time — 시각 디자인

## 범위와 책임

이 문서는 승인된 랜딩 프로토타입("랜딩 볼드 시안" 아티팩트), `feat/web-language-switch`의 랜딩 재설계, "iMessage 연결 화면 시안" 캔버스에서 가져온 시각 방향을 정의합니다. 2026-10-13의 식물·올리브(Thyme) 방향을 앱 전체에서 대체합니다. 2026-10-12 킥오프에서 디자인 시스템과 UX 흐름은 은우가 맡았고, 은우는 2026-10-29 잉크를 모든 화면의 방향으로 정했습니다.

**Find Me a Time**은 제품이고, **Thyme**은 일정 조율 어시스턴트입니다. [디자인 원칙](documentations/03_design_principles.md)이 상호작용 방향을 책임집니다. [원페이저](documentations/01_one_pager.md), [PRD](documentations/02_product_requirements.md), [역량 명세](openspec/specs/)가 제품 범위와 동작을 책임집니다. 시각 스타일은 이들의 동의, 개인정보, 예약 규칙을 지켜야 합니다.

컴포넌트 구조, 메시지·작성창 상호작용, 반응형 마감은 [참고 저장소](documentations/technical_specification/02_frontend_architecture.md#reference-repositories)의 Vercel chatbot과 eve 채팅 템플릿을 연구해 이 팔레트에 맞게 가져옵니다.

**구현된 곳.** 공개 랜딩(`/`와 `/?flow=imessage`)과 `/app`의 iMessage 연결 단계는 `.ink` 범위로 묶인 `apps/web/app/_components/ink/ink.css`에서 이 토큰을 사용합니다([`host-imessage-channel` D18](openspec/changes/host-imessage-channel/proposal.md#decisions)). 앱의 나머지(`/app`의 대화, 호스트 페이지, 예약, 개인정보)는 옮겨질 때까지 `apps/web/app/globals.css`의 이전 Thyme 토큰을 그대로 사용합니다. [알려진 공백](#known-gaps)을 참고하십시오.

## 분위기

차분하고 정확하며, 조용히 대담한 느낌입니다. 좁고 굵은 워드마크와 헤드라인을 평이하고 읽기 쉬운 제품 UI, 차가운 오프화이트 종이, 넉넉한 여백과 짝지읍니다. 유능한 어시스턴트가 보낸 분명한 메시지처럼, 직접적이고 믿을 수 있으며 쉽게 실행할 수 있는 느낌을 주어야 합니다.

짙은 잉크 블루, 차가운 회청색 중성색, 가는 선, 굵고 좁은 제목을 사용합니다. 대화 자체를 주요 시각 요소로 두며, 일정 검토에는 장식보다 명료함이 필요합니다.

## 로고

현재 마크는 알파 마스크(`apps/web/public/logo-mask.png`)로 제공되어 `logo` 색으로 칠해지므로, 별도의 색상 파일 없이 팔레트를 따릅니다. 잉크 헤더는 넓은 화면에서 20px, 960px까지 17px, 휴대폰에서 10px로 워드마크 옆에 보여 줍니다.

새 로고가 진행 중입니다(2026-10-14 회의): 캘리그래피 마크, SVG 파비콘, moonie 같은 캐릭터 참고를 받는 채팅 프로필 사진입니다. 그전까지는:

- 마크와 워드마크를 별개 요소로 둡니다. 워드마크는 워드마크 서체로 쓴 실제 텍스트입니다.
- 밝은 표면에는 `logo`를 사용합니다. 대비나 인쇄에 필요하면 단색 `ink` 버전이 적합합니다.
- 늘이거나, 회전하거나, 그림자를 넣거나, 장식 배지로 감싸거나, 로딩 표시로 애니메이션하지 않습니다.
- 로고가 홈 링크의 유일한 내용이면 링크에 제품명 접근성 레이블을 붙입니다. 주변 텍스트가 이미 식별해 주면 이미지는 장식으로 취급합니다.

| 성공 | `success` | `#3F6142` | 확인된 성공 결과 |

토큰 이름 `botanical`은 코드와 이 문서가 계속 일치하도록 이전 팔레트에서 유지했으며, 값은 이제 차분한 슬레이트입니다. `warning`과 `success`는 아직 잉크 화면에서 쓰지 않으므로 그대로 가져왔습니다. 상태 배지를 만들 때 잉크 팔레트에 맞춰 확인합니다.

앱 전체에서 의미 역할을 사용합니다. 슬레이트 선은 캔버스 위에서 3.21:1 대비로, 필수 컨트롤 경계에는 충분하지만 일반 작은 텍스트에는 부족합니다. 장식 선은 1.32:1이므로 상호작용 컨트롤의 유일한 경계가 될 수 없습니다.

평면 토큰 쌍의 대비는 ink/canvas 14.51:1, muted-ink/canvas 5.82:1, muted-ink/soft-surface 5.17:1, on-primary/primary 10.63:1, logo/canvas 6.06:1입니다. 오류, 주의, 성공 텍스트는 각각 캔버스 위에서 6:1을 넘습니다. 질감, 상태 채움, 투명도를 더한 뒤에는 실제 조합을 다시 검증합니다.

**예외:** Google 로그인 버튼은 팔레트 대신 Google의 어두운 버튼 사양(채움 `#131314`, 선 `#8E918F`, 레이블 `#E3E3E3`, 컬러 G)을 따릅니다. iMessage 화면은 메시지 앱을 묘사하는 곳에서 메시지 앱 고유의 색, 즉 초록 글리프와 메시지 미리보기의 파란 말풍선을 보여 줍니다.

## 종이 재질과 질감

페이지 배경은 고운 결이 있는 **차가운 무광 종이**입니다. `ink.css`는 이를 180px 인라인 SVG 노이즈 타일(`feTurbulence`, 프랙털 노이즈)로 별도의 `::before` 레이어에 3% 불투명도(최대 4%), `pointer-events: none`으로 그립니다.

- 텍스트, 입력, 버튼, 채팅 메시지, 제안 세부 정보, 캘린더, 오버레이는 깨끗한 표면에 둡니다. 결은 주변 캔버스에만 보입니다.
- 페이지 컨테이너나 그 내용에 투명도를 적용하지 않습니다.
- 질감은 재질을 암시하는 데만 씁니다. 얼룩, 주름, 줄 선, 강한 노이즈, 가짜 접힌 종이 컨트롤을 피합니다.
- 질감은 정적으로 둡니다. 움직이는 결, 패럴랙스, 스크롤 재질 효과는 없습니다.
- 강제 색상 모드와 인쇄에서는 질감을 생략합니다. `ink.css`는 아직 그렇게 하지 않습니다.

## 타이포그래피

워드마크와 표시 제목에는 **Big Shoulders**(굵기 800, `opsz` 72), 본문과 인터페이스 텍스트에는 **Geist**, 프롬프트·링크·기술 레이블에는 **Geist Mono**를 사용합니다. 시스템 대체 글꼴을 유지합니다.

Big Shoulders는 좁은 서체이므로 제목에 제목 배율 **1.19**를 곱합니다. 그러면 가장 넓은 헤드라인 줄이 Geist일 때와 거의 같은 폭이 됩니다. Big Shoulders는 라틴 문자만 지원하므로 한국어 제목은 배율 1을 씁니다.

| --- | --- | --- | --- | --- | --- |
| 워드마크 | Big Shoulders | `clamp(26px, 3.2cqi, 33px)`; 휴대폰에서 × 0.78 | 800 | 1 | 헤더 브랜드 |
| 표시 | Big Shoulders | `clamp(32px, 4.6cqi, 56px)` × 1.19; 휴대폰에서 26px × 1.19 | 800 | 1.04 | 랜딩 헤드라인 |
| 페이지 제목 | Big Shoulders | `clamp(30px, 4cqi, 42px)` × 1.19 | 800 | 1.08 | 연결 단계와 핸드오프 화면 |
| 섹션 제목 | Big Shoulders | `clamp(21px, 2.4cqi, 27px)` × 1.19 | 800 | 1.2 | 랜딩 섹션 |
| 컴포넌트 제목 | Geist | 16–18px | 700 | 1.3–1.4 | 카드 제목, 단계 제목 |
| 리드 | Geist | 18px; 휴대폰과 이후 화면에서 16–17px | 400 | 1.6 | 헤드라인 아래 텍스트 |

표시 자간은 -0.04em에서 0 사이로 두고, 본문은 기본 자간을 씁니다. 필기체, 자간을 크게 벌린 문단, 밀집한 컨트롤의 표시 서체를 피합니다. iOS가 확대하지 않도록 입력은 최소 16px 텍스트를 씁니다. 관련 있을 때는 날짜를 명시적 시간대와 함께 표시하고, 전화번호, 코드, 정렬된 시간, 단계 번호에는 고정폭 숫자를 씁니다.

## 레이아웃과 간격

프론트매터 척도의 4px 간격 기반을 사용합니다. 기본 간격은 컨트롤 안에서 8–12px, 섹션 안에서 16–24px, 섹션 사이에서 28–44px입니다. `ink.css`는 시각적 맞춤을 위해 몇 가지 중간값(10, 14, 22px)도 씁니다.

내용은 1120px 안에 가운데 정렬합니다. 측면 여백은 `clamp(20px, 5cqi, 56px)`입니다. 채팅 열은 720px, 간단한 양식과 핸드오프 화면은 약 460px, 랜딩 예시 스레드는 384px, 리드는 한 줄에 약 46자로 둡니다.

레이아웃은 창이 아니라 페이지 컨테이너의 폭(컨테이너 쿼리)에 반응합니다:

- **600px 이하:** 휴대폰 레이아웃. 예시 채팅이 헤드라인 바로 아래에 스와이프 카드로 놓이고, Google 버튼은 전체 폭입니다.
- **601px 이상:** 데스크톱 배치. 왼쪽에 소개, 오른쪽에 예시 스레드가 놓입니다.
- **960px 이하:** 헤더 마크가 작아지고, 히어로 안쪽 여백이 0으로 줄어듭니다.

호스트 대화는 현재 대화와 작성창에 쉽게 닿을 수 있어야 합니다. 일정 제안은 미팅 맥락, 제안된 날짜와 시간대, 길이, 장소, 현재 상태, 허용된 다음 동작 순서로 분명하게 배치합니다. 스타일은 각 참여자가 접근할 수 있는 세부 정보나 동작을 바꾸지 않습니다.

## 모양, 선, 높이

작은 버튼과 휴대폰 스와이프 카드에는 6px, Google 버튼·메뉴 항목·QR과 복사 행에는 8px, 버튼·입력·코드 블록에는 10px, 카드·말풍선·메뉴에는 12px, 작성창·메시지 미리보기·방법 카드에는 14px, 채팅 창·예시 스레드·팝업에는 16px 반경을 씁니다. 메시지 말풍선은 화자에 가장 가까운 모서리를 4px로 깎습니다. 완전히 둥근 모양은 아바타, 언어 버튼, 카운터, 캐러셀 점에만 씁니다.

기본은 평평한 표면과 1px 선입니다. 떠 있는 표면에는 절제된 그림자를 줍니다: 예시 스레드와 페이지 안 패널에는 `0 8px 24px rgb(48 54 43 / 0.08)`, 메뉴에는 `0 12px 32px rgb(30 36 48 / 0.14)`, 팝업에는 `0 24px 60px rgb(30 36 48 / 0.22)`입니다. 광택 하이라이트, 유리 효과, 겹친 종이 흉내를 넣지 않습니다.

| 입력 | 깨끗한 표면, 슬레이트 경계, 10px 반경, 48px 높이, 상시 레이블, 16px 이상 텍스트, 오류로 바뀌는 인라인 도움말 |
| 작성창 | 깨끗한 표면, 슬레이트 경계, 14px 반경, 비활성 상태가 있는 44px 잉크 블루 전송 버튼 |
| 어시스턴트 메시지 | 부드러운 워시 말풍선, 잉크 텍스트; 창 머리에 아바타와 "Thyme" 표시 |
| 사용자 메시지 | 흰 텍스트의 잉크 블루 말풍선, 오른쪽 정렬 |
| 에이전트 프롬프트 | 코드 블록: 부드러운 워시, 장식 선 테두리, 10px 반경, 13px 모노, 복사 버튼, 여덟 줄을 넘으면 스크롤 |
| 전송 패널과 팝업 | 메시지 앱 스타일 미리보기 안의 연결 메시지, 그다음 경로마다 방법 카드 하나(메시지 열기, QR 코드, **복사(Copy)**); 컴퓨터에서는 팝업, 휴대폰에서는 전체 화면으로 열림 |
| 계정·언어 메뉴 | 버튼이 44px 항목을 가진 깨끗한 표면 메뉴를 엶 |
| 대화 카드 | 최신 메시지 뒤에 한 번에 하나만 열림; 답하면 기록에 남는 한 줄 영수증(값, 출처 배지, **편집(Edit)**)으로 접힘; 질문 하나를 16px 제목으로, 출처 배지와 함께 제안 값, 짧은 이유 하나, 그다음 동작; 가로 16px, 세로 12px 안쪽 여백; 작성창 위의 휴대폰 화면에 들어맞고, 긴 편집기는 카드 안에서 스크롤([한 번에 하나만 생각하기](documentations/03_design_principles.md#4-one-thing-to-think-about-at-once)) |
| 제안 카드 | 아직 잉크로 옮기지 않음. 간결한 제목과 구조화된 세부 정보, 두드러진 현재 동작, 보이는 상태 텍스트 |
| 상태 배지 | 아직 잉크로 옮기지 않음. 짧고 명시적인 상태 레이블, 절제된 색조, 선택적 아이콘; 색만으로 표시하지 않음 |
| 대화상자 | 깨끗한 표면, 16px 반경, 접근 가능한 제목, 분명한 동작 순서, 유지되는 포커스 동작 |

앱에는 선택된 shadcn과 대화 컴포넌트 방향을 사용합니다. 그 변형을 우선하고, 호출 지점마다 색상과 타이포그래피를 덮어쓰기보다 공유 레시피를 갱신합니다. 작업마다 알맞은 정보 밀도를 유지합니다. 여유로운 랜딩 페이지 때문에 캘린더 검토가 번거로워져서는 안 됩니다.

## 목소리와 움직임

직접적이고 따뜻한 문구를 씁니다: "Thyme에게 메시지 하나를 보내세요(Send Thyme one message)", "여기 웹 채팅에서 설정하기(Set up here in web chat)", "캘린더가 연결되었어요(Your calendar is connected)". Thyme을 어시스턴트 정체성으로, Find Me a Time을 제품 정체성으로 보여 줍니다. 대기, 제안, 승인, 예약 상태를 정확히 설명하고, 서비스가 확인한 뒤에만 성공을 알립니다.

컨트롤에는 150ms 색상 전환을 씁니다. 받은 코드는 320ms에 걸쳐 미끄러져 들어오고, 페이지가 메시지를 기다리는 동안 스피너가 돌며, 상태 마크는 한 번 그려집니다. 메시지가 스트리밍되는 동안 읽는 위치를 안정적으로 유지합니다. 동작 줄이기 설정을 존중합니다: `ink.css`는 `prefers-reduced-motion`에서 이것들을 끕니다.

## 반응형과 접근성 동작

- 기본 컨트롤, 메뉴 항목, 휴대폰의 아이콘 동작에는 최소 44px 터치 영역을 씁니다. 아이콘만 있는 버튼에는 접근 가능한 이름을 붙입니다.
- 3px 간격의 보이는 2px 실선 포커스 윤곽을 유지합니다.
- 일반 텍스트는 4.5:1, 큰 텍스트와 필수 컨트롤 경계는 3:1 대비를 목표로 합니다. 질감 영역을 포함해 렌더링된 상태를 검증합니다.
- 텍스트가 줄바꿈되고, 레이블이 늘어나고, 긴 이름과 링크가 끊길 수 있게 합니다. 320px와 200% 확대에서 가로 페이지 스크롤을 피합니다.
- 작은 화면에서는 제안 세부 정보와 동작을 쌓고, 시간대 레이블을 보이게 둡니다. 작성창 주변의 모바일 키보드와 안전 영역 여백을 고려합니다.
- 상태 색은 텍스트와 짝짓고, 의미 있는 제목과 필드 레이블을 유지하며, 관련 대기와 오류 상태를 읽기를 방해하지 않게 알립니다.

## 해야 할 것과 하지 말 것

**해야 할 것:** 굵고 좁은 제목, 차가운 중성색, 잉크 블루 동작, 은은한 종이 결, 넉넉한 읽기 열, 명시적인 일정 상태를 씁니다.

**하지 말 것:** 세부 작업 내용 뒤에 질감을 두기, 작은 텍스트에 슬레이트 선 색 쓰기, 밀집한 컨트롤을 표시 서체로 쓰기, 단색 팔레트로 오류를 숨기기, 분명한 확인 대신 시각적 차분함으로 때우기.

## 제안된 구현 매핑

잉크 화면은 이 토큰을 `.ink` 아래의 일반 CSS 변수로 구현합니다(`apps/web/app/_components/ink/ink.css`). 앱은 Next.js, Tailwind/shadcn, 접근 가능한 대화 UI 방향을 유지하므로, 앱의 나머지를 옮긴다는 것은 이 토큰을 `apps/web/app/globals.css`의 shadcn 테마 변수로 옮기는 것이며, 그 뒤 `.ink`는 화면별 규칙만 남길 수 있습니다.

canvas/ink는 background/foreground로, surface는 card/popover로, primary/on-primary는 primary/primary-foreground로, 부드러운 워시는 secondary/muted/accent로, 보조 잉크는 muted-foreground로, 장식 선은 border로, 필드 경계는 input으로, 포커스는 ring으로 매핑합니다. hover/pressed/logo/warning/success 역할은 명시적으로 유지합니다. 반경 척도는 sm 6px, md 10px, lg 12px, xl 16px로 매핑합니다. 표시·제목 글꼴은 Big Shoulders 800(`opsz` 72)으로, sans 글꼴은 Geist로 지정합니다. 장식 종이 레이어는 깨끗한 컨트롤과 내용과 분리해 둡니다.

## 반복 가이드

디자인을 적용할 때는 캔버스, 종이 레이어, 텍스트 대비, 타이포그래피부터 시작합니다. 그다음 공유 컨트롤, 대화 표면, 제안 카드를 갱신합니다. 마지막으로 브랜드 자산과 반응형 마감을 합니다.

랜딩 페이지, 긴 메시지가 있는 대화, 호스트 승인을 기다리는 제안, 검증 오류, 키보드 포커스를 받은 대화상자를 검토합니다. 375px, 800px, 1280px 폭, 200% 확대, 동작 줄이기, 강제 색상을 확인합니다. 바뀐 코드에 관련된 앱 검사를 실행하며, 문서 검증만으로는 렌더링된 테마를 검증할 수 없습니다.

## 알려진 공백

- 이 방향을 쓰는 곳은 랜딩과 iMessage 연결 단계뿐입니다. `/app`의 대화, 호스트 페이지, 예약, 개인정보 페이지는 여전히 `apps/web/app/globals.css`의 Thyme 토큰(따뜻한 아이보리 위의 올리브, Merriweather 제목)을 쓰며, `apps/web/app/theme.test.ts`와 `tests/e2e/theme.test.ts`는 옮겨질 때까지 그 Thyme 값을 검사합니다.
- 로고 마스크는 10–20px로 표시되며 단순화한 작은 크기 버전이 없습니다. 새 캘리그래피 로고, SVG 파비콘, 채팅 프로필 사진이 진행 중입니다.
- 예시 스레드의 그림자는 아직 이전 올리브 잉크 색(`rgb(48 54 43)`)을 쓰고, 메뉴와 팝업 그림자는 잉크(`rgb(30 36 48)`)를 씁니다. 그림자를 토큰화할 때 맞춥니다.
- 잉크 종이 질감은 아직 강제 색상 모드와 인쇄에서 제거되지 않습니다.
- `warning`과 `success`는 쓰이지 않은 채 올리브 팔레트에서 가져왔습니다. 상태 배지에서 다시 확인합니다.
- 다크 테마는 없습니다. 별도의 대비·시각 검토가 필요하며, 팔레트나 질감을 자동으로 반전하지 않습니다.
