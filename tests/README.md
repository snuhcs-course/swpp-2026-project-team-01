# Application verification

Photon receiver tests verify byte-exact signatures, replay windows, transferred receiver IDs, private routing, body limits and commit-before-acknowledgment. A compatibility probe exercises the installed eve adapter without network calls and records its early acknowledgment and lack of an application-owned send identity. Local database coverage verifies service-only ingress, private RLS tables, project/message deduplication, changed-payload rejection and atomic inbox/job creation. Integration tests race eight identical signed receipts, lose a database response after commit and observe a real row-lock wait while disabling the receiver. These tests establish transport receipt only; linking, downstream authority, outbound reconciliation and live iMessage acceptance remain separate gates.

These directories contain replacement integration and browser tests. HTTP security unit tests live in `lib/server/identity/`; `scripts/smoke-runtime.mjs` exercises the built production servers without model calls.

- `integration/`: shared domain, eve/web runtime, authorization and channel boundaries.
- `runtime/`: isolated actual-eve fixtures with deterministic model output and real database effects.
- `e2e/`: complete browser journeys against the rebuilt application.

`npm run test:browser` runs suites sequentially against the shared local database and requires a built web application, local Supabase/Mailpit, Chromium (`npx playwright install chromium`) and free port 3000. It verifies Google-only sign-in and real local Supabase PKCE exchange (a synthetic completed Google response seeds `auth.flow_state`; no live Google consent is claimed), rejected email login, cancelled/wrong-browser callbacks, invalid/valid invitation redemption, reload, logout including a copied session, callback replay, forged cookies, private-link exchange, cross-browser denial, closed-state privacy and deduplicated waitlist submission. It also starts an isolated actual-eve mock-model fixture and verifies host/requester chat, chronological replay, a dropped stream, a lost POST acknowledgment retried with one input, and live revocation clearing the transcript. It checks no-store responses, HttpOnly cookies, keyboard focus, 320/390px reflow and CSS 200% magnification. Screenshots stay in ignored `.local/rebuild/browser-screenshots/`. CSS magnification does not certify native browser zoom or actual iPhone Safari/iMessage handoffs; those release checks remain pending. The fixture rejects non-loopback Supabase targets and sends email only to local Mailpit.

Keep unit tests beside their modules and database tests in `supabase/tests/`. Run `npm run check` for types, HTTP security, documentation and SMTP tests. After `npm run build`, run `npm run test:runtime` for health, response headers and anonymous denial at every exposed eve session endpoint. Run `npm run db:test` against the disposable local Supabase stack. The evidence ledger distinguishes the implemented authorization/recovery checks from outstanding browser and provider journeys; do not count empty directories as coverage.

`npm run test:integration` requires the disposable local Supabase stack. It creates and removes one synthetic local Auth user, verifies real token validation and service-only RPC permissions, denies unadmitted conversation access, then verifies immediate logout invalidation. The test rejects non-loopback targets and does not load remote credentials from `.env`. CI runs it in the database job after the migration reset and pgTAP suites. After integration, runtime and browser fixtures, CI reruns the complete SQL suite against the same database without resetting it. This final gate also runs after a test failure when the baseline passed and the job was not cancelled, so leaked queue publications or broken domain invariants cannot hide behind a clean initial reset.

The same integration command opens independent PostgreSQL connections inside the local Supabase Docker container to race conversation-tool writes against logout. It observes actual blocking locks before releasing either transaction, verifies both commit orders, and checks session expiry during a lock wait. Exact synthetic fixtures are removed afterward. ## Local OAuth compatibility probe

`npm run probe:oauth` requires the running disposable Supabase CLI **2.119.0** stack and its GoTrue **v2.197.0** Docker image. It starts a separate loopback-only Auth process on an ephemeral port with OAuth enabled, sharing only the local database/signing configuration. It does not restart the main stack, load project `.env` files, send email, use hosted Auth, or change production login settings. A synthetic local password user is a test fixture, not an MVP login method.

The probe exercises discovery, dynamic public-client registration, browser-consent API binding, S256 PKCE, JSON and form resource mismatch, code reuse, refresh audience/resource handling and grant revocation. It prints only sanitized outcomes. Exit **2** is the currently observed resource-isolation failure; it is not a passing release gate. Exit **1** indicates an unexpected probe/setup/cleanup failure. The exact pinned source version is recorded in its output; after upgrading Auth, revise and rerun this compatibility probe rather than preserving expected failures as product behavior.

Cleanup attempts client deletion, user deletion and temporary container removal independently. Auth soft-deletes client records, so inactive client tombstones can remain in the disposable database; it removes the synthetic user and stops the extra process. If interrupted externally, identify this run’s `fmat-oauth-probe-<UUID>` container and its matching client/user before removing them. Never remove the ordinary Supabase stack or unrelated probe identities. This test does not establish hosted-version behavior, full browser/terminal login, requester grants or named-client compatibility.

## Browser and shared-contract import boundaries

`npm run check:boundaries` runs in `npm run check` and CI. It parses every application `use client` root and every shared contract, following local runtime imports/re-exports, the configured `@web/` alias, literal dynamic imports and `require` calls. It rejects reachable `lib/server/`, `agent/`, `.server.*`, Node builtins, `server-only`, private/computed `process.env` reads, unresolved local imports and unknown dynamic targets. Five negative/positive fixture tests cover a cyclic alias/barrel/dynamic chain to privileged code, standalone contract leakage, erased type imports, comments, public variables, private environment reads and unsupported targets, including runtime imports of test-named files.
