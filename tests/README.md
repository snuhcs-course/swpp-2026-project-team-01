# Application verification

Photon receiver tests verify byte-exact signatures, replay windows, transferred receiver IDs, private routing, body limits and commit-before-acknowledgment. A compatibility probe exercises the installed eve adapter without network calls and records its early acknowledgment and lack of an application-owned send identity. Local database coverage verifies service-only ingress, private RLS tables, project/message deduplication, changed-payload rejection and atomic inbox/job creation. Integration tests race eight identical signed receipts, lose a database response after commit and observe a real row-lock wait while disabling the receiver. These tests establish transport receipt only; linking, downstream authority, outbound reconciliation and live iMessage acceptance remain separate gates.

These directories contain replacement integration and browser tests. HTTP security unit tests live in `lib/server/identity/`; `scripts/smoke-runtime.mjs` exercises the built production servers without model calls.

- `integration/`: shared domain, eve/web runtime, authorization and channel boundaries.
- `runtime/`: isolated actual-eve fixtures with deterministic model output and real database effects.
- `e2e/`: complete browser journeys against the rebuilt application.

`npm run test:browser` requires a built web application, local Supabase/Mailpit, Chromium (`npx playwright install chromium`) and free port 3000. It verifies email PKCE sign-in, invalid/valid invitation redemption, reload, logout including a copied session, callback replay, forged cookies, private-link exchange, cross-browser denial, closed-state privacy and deduplicated waitlist submission. It also starts an isolated actual-eve mock-model fixture and verifies host/requester chat, chronological replay, a dropped stream, a lost POST acknowledgment retried with one input, and live revocation clearing the transcript. It checks no-store responses, HttpOnly cookies, keyboard focus, 320/390px reflow and CSS 200% magnification. Screenshots stay in ignored `.local/rebuild/browser-screenshots/`. CSS magnification does not certify native browser zoom or actual iPhone Safari/iMessage handoffs; those release checks remain pending. The fixture rejects non-loopback Supabase targets and sends email only to local Mailpit.

Keep unit tests beside their modules and database tests in `supabase/tests/`. Run `npm run check` for types, HTTP security, documentation and SMTP tests. After `npm run build`, run `npm run test:runtime` for health, response headers and anonymous denial at every exposed eve session endpoint. Run `npm run db:test` against the disposable local Supabase stack. The evidence ledger distinguishes the implemented authorization/recovery checks from outstanding browser and provider journeys; do not count empty directories as coverage.

See the [implementation plan](../documentations/technical_specification/04_implementation_plan.md).

`npm run test:integration` requires the disposable local Supabase stack. It creates and removes one synthetic local Auth user, verifies real token validation and service-only RPC permissions, denies unadmitted conversation access, then verifies immediate logout invalidation. The test rejects non-loopback targets and does not load remote credentials from `.env`. CI runs it in the database job after the migration reset and pgTAP suites.

The same integration command opens independent PostgreSQL connections inside the local Supabase Docker container to race conversation-tool writes against logout. It observes actual blocking locks before releasing either transaction, verifies both commit orders, and checks session expiry during a lock wait. Exact synthetic fixtures are removed afterward. These database concurrency checks complement the real Auth test; actual eve process termination and replay are tested separately.

`npm run test:conversations` requires the same disposable local Supabase stack. It builds an isolated eve 0.71.3 fixture using the production channel, a documented mock model, and a tool that pauses after a real command commit. It kills the process group, restarts with `eve dev --resume`, retries the same accepted message and verifies one database effect, two-message continuity, cursor reconnect, cross-request denial and revoked access. Fixture output stays under ignored `.local/rebuild/`. It uses `WORKFLOW_INLINE_OWNERSHIP_LEASE_SECONDS=5` only in that child process: the bundled Workflow default is 860 seconds, which exceeded the original 30-second assertion window. This accelerates lease expiry without modifying persisted workflow records or production configuration. It also commits an input without sending it and verifies that an authenticated recovery sweep delivers it without a browser retry. The check does not establish managed Vercel workflow recovery latency.

Calendar consent coverage adds AES-GCM authentication/context tests, Google scope and verified-identity contracts, service-only SQL guards, concurrent callback consumption and revocation while a provider exchange is pending. Browser tests exercise real authorization URLs, HttpOnly state binding, wrong-browser denial, denial/resumption, replay and forged success notices for hosts and requesters. These fixtures do not grant live Google consent or prove refresh/calendar-read behavior.

Calendar selection tests verify pagination, malformed/partial failures, refresh preservation and invalid grants. Real local Auth/database integration pauses provider reads/refresh to test reconnect, disconnect and logout before results return, and checks that current permissions override stale UI choices. SQL tests cover service-only access, cross-host/guest rejection, read-only destinations, missing selections and stale grant/setup revisions. The browser journey exercises actual cookie routes and persistence with `google-fixture.mjs` preloaded only into its isolated Next.js process; the fixture intercepts outbound Google list requests for isolated host/requester tokens and requester free/busy calls. It verifies explicit choices, duplicate-name distinction, disabled read-only destinations, keyboard selection, visible checked state, reload and disconnect. This is deterministic provider evidence, not live Google consent or Calendar access.

Requester availability tests cover selected-calendar scope, exact free/busy range coverage, missing calendars, provider errors, half-open interval merging, DST ambiguity, refresh and cross-request denial. Real-database integration pauses an in-flight read while manual replacement removes its authority, and checks stale generation/revision rejection plus closure cleanup. SQL tests verify failed reads invalidate decisions, manual confirmation is explicit and current, and partial details remain normalizable. The browser journey checks a failed read, a successful retry clearing both the persisted flag and paused notice, a later failure, and explicit manual replacement. It includes 320px button reflow and local screenshots. These deterministic checks do not establish live Google consent, refresh or AC-27 acceptance.

Host setup coverage includes strict partial contracts and rejection of model confirmation; private SQL drafts/reviews, provenance, idempotency conflicts, reserved handles, cross-host/guest denial and Auth expiry; and real-Auth integration with changing Calendar permissions, a concurrent draft edit during provider preflight, stale-settings refresh preserving answers, and lost-confirmation replay. Browser coverage includes profile/schedule edits, explicit online and physical choices, per-meeting location/per-trip transportation, independent travel buffer, stale-review refresh, consent denial/reload preserving the draft, and persisted confirmation. Google permission responses remain fixtures. This does not certify Calendar analysis, live Google consent, iMessage linking or complete AC-28.

Calendar analysis adds scoped/paginated event-reader tests, body/page/range failure boundaries, recurring-instance input, all-day/DST normalization, ignored cancelled/free/declined entries, sparse/no-gap summaries and source-text exclusion. Real Auth/database tests race setup edits and reconnection against a scan, reject revoked event access on application, preserve explicit preferences, suppress repeated dismissed results and expire snapshots. SQL tests verify private access, consent, selected IDs, pending-review invalidation and model projection redaction. Browser fixtures exercise failed scan → reload → fresh selection → private suggestions → draft-only application, duplicate names and 320px action containment. Provider responses remain deterministic fixtures; live Google analysis and complete AC-28 are not certified.

Guidance tests cover no-history defaults, persisted dismissal, prior-value precedence, explicit physical preferences and online skips. Host setup SQL/integration tests verify progress replay/conflicts, model/guest denial and unchanged saved policy. The browser journey checks skip/reload, blank manual controls after dismissal, explicit re-offering, and separate transportation/buffer continuation.

Calendar review tests cover invalid candidate references, explicit mode requirements, edited-window/place origins, conflicting known values, immutable decision replay and source preservation through later edits. The browser suite includes a separate no-history host completing guided defaults, physical preferences and current confirmation without any event scan, in addition to rich Calendar review. Both use the isolated Google fixture server; live provider acceptance is separate.

Extracted-answer review uses the actual local eve channel, production setup tools and deterministic model output. A synthetic host describes a full set of preferences, reviews initially unselected answers, reloads, explicitly selects them, retries a lost acceptance response and then confirms exact settings. Assertions distinguish assistant origins from host provenance, ensure no premature policy/booking effect, and verify accepted answers are not asked again. Contract tests cover partial choices, missing values, online skips, dismissal and stale drafts. This does not establish live model or linked-iMessage acceptance.

Photon linking tests cover HMAC/encryption context, protected browser-proof cookies, frozen routes and message IDs, current authorization after SDK preflight, acceptance/delivery distinction and no automatic resend. SQL tests cover service-only access, current admission/session/browser, immutable requests/guesses, expiry, per-host and per-recipient limits, replacement/cancellation, single-use links, stale unlink/replay, disabled receivers and worker fencing. Real local Auth integration races eight starts and two workers, loses provider and database acknowledgments, races two hosts for one number, observes a blocked database read, and revokes a session during provider preflight. Provider calls are isolated fixtures; no live recipient, inbound linked authority or UI completion is asserted.
