## Local OAuth compatibility probe

`npm run probe:oauth` requires the running disposable Supabase CLI **2.119.0** stack and its GoTrue **v2.197.0** Docker image. It starts a separate loopback-only Auth process on an ephemeral port with OAuth enabled, sharing only the local database/signing configuration. It does not restart the main stack, load project `.env` files, send email, use hosted Auth, or change production login settings. A synthetic local password user is a test fixture, not an MVP login method.

The probe exercises discovery, dynamic public-client registration, browser-consent API binding, S256 PKCE, JSON and form resource mismatch, code reuse, refresh audience/resource handling and grant revocation. It prints only sanitized outcomes. Exit **2** is the currently observed resource-isolation failure; it is not a passing release gate. Exit **1** indicates an unexpected probe/setup/cleanup failure. The exact pinned source version is recorded in its output; after upgrading Auth, revise and rerun this compatibility probe rather than preserving expected failures as product behavior.

Cleanup attempts client deletion, user deletion and temporary container removal independently. Auth soft-deletes client records, so inactive client tombstones can remain in the disposable database; it removes the synthetic user and stops the extra process. If interrupted externally, identify this run’s `fmat-oauth-probe-<UUID>` container and its matching client/user before removing them. Never remove the ordinary Supabase stack or unrelated probe identities. This test does not establish hosted-version behavior, full browser/terminal login, requester grants or named-client compatibility.
