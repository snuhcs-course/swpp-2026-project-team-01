## Decisions

On the first settings insert, mark the one-time offer pending. Accepting or skipping consumes it in the same transaction. Create one marked sample in the existing request and proposal model, with fictional terms and no guest access link. Reusing the request projection and decision buttons gives the host the same review experience on each supported surface.

Handle practice actions through their own command and exclude samples at the ordinary host command lock. This keeps approvals, notifications, and calendar writes behind the existing real-request path. Sample creation bypasses guest admission and evaluation jobs. Closed samples remain addressable to show completion but are excluded from the inbox and never treated as a pending decision.

A linked offer and an active sample hold the chat selection when another request arrives. The host can explicitly switch to a real request while practising. WhatsApp sample notices expire with the messaging window and have no real-request template fallback.
