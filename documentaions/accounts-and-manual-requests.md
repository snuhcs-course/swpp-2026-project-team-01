# Caltalk 계정과 연동 없는 요청

## 지금 사용할 수 있는 것

- 사이트: https://caltalk-mvp.vercel.app
- 기존 Google 로그인과 캘린더 자동 확인은 유지합니다.
- 요청 링크에서 **연동 없이 시간 선택** → 이름·이메일·미팅 목적 입력 → **선택 가능한 시간 보기** → 시간 1–3개 선택 → 제출 순서로 사용합니다. 가입이나 Google 연결은 필요 없습니다.
- 공개 시간 중 호스트 일정과 충돌하지 않는 시간만 보여주고 제출할 때 다시 확인합니다. 본인의 다른 일정은 직접 확인해야 합니다.
- 호스트는 수동 요청 표시를 보고 후보 하나를 수락합니다. 수락할 때만 Google 일정 생성과 입력한 이메일로 초대 알림 발송을 요청합니다. 이메일 소유 여부·배달 여부는 검증하지 않습니다.

## Caltalk 계정 사용 순서

1. 첫 화면에서 시작하여 **회원가입**을 선택하고 이메일·8자 이상 비밀번호를 입력합니다.
2. 인증 메일을 가입했던 브라우저에서 열고 인증합니다. 이후 이메일·비밀번호로 로그인합니다.
3. **내 계정**에서 Google Calendar를 처음 연결합니다. 기존 호스트와 같은 Google 계정을 연결하면 이전 링크 기록도 이어집니다.
4. 다음부터는 Caltalk 로그인만 합니다. 요청 링크에서도 저장된 연결로 자동 확인할 수 있습니다.

Google 연결은 취소·만료·추가 권한 필요 시 다시 동의해야 합니다. Google 외부 앱 테스트 모드에서는 Calendar 권한을 포함한 갱신 토큰이 일반적으로 7일 후 만료될 수 있습니다. 계정 기능이 이 제한을 없애지는 않습니다. [Google 공식 문서](https://developers.google.com/identity/protocols/oauth2#expiration)

## 아직 필요한 설정: 회원가입 인증 메일

앱의 가입 기능과 인증 복귀 주소는 구현·배포했지만 일반 팀원에게 인증 메일을 보내기 위한 **SMTP 서비스가 아직 연결되지 않았습니다.** 현재 Supabase 이메일 확인은 켜져 있습니다. 확인 절차를 끄거나 관리자 권한으로 가입을 우회하지 않았습니다.

Supabase의 기본 메일 서비스는 조직에 허용된 이메일만 수신할 수 있는 등의 제한이 있습니다. Google OAuth 테스트 사용자 등록과는 별개입니다. [Supabase 공식 SMTP 안내](https://supabase.com/docs/guides/auth/auth-smtp)

메일 서비스가 준비되면 Supabase 프로젝트의 Authentication 이메일/SMTP 설정에 발신 주소·발신자명·SMTP 호스트·포트·사용자명·비밀번호를 등록해야 합니다. 서비스에 따라 발신 도메인 인증도 필요합니다. 이 값들은 저장소나 채팅에 공개하지 않습니다. 인증 메일이 준비되지 않은 동안 기존 Google 로그인을 사용할 수 있습니다.

이미 반영한 값:

- Site URL: `https://caltalk-mvp.vercel.app`
- 허용 복귀 URL: `http://localhost:3000/api/account/confirm`, `https://caltalk-mvp.vercel.app/api/account/confirm`
- 로컬 및 Vercel 환경 변수: `SUPABASE_PUBLISHABLE_KEY` (Auth 클라이언트용). DB 서버 키와 구분합니다.

## 구현과 확인 범위

계정 세션은 Supabase Auth가 담당하고 서버에서 사용자 신원을 확인합니다. Google 토큰은 암호화해 DB에 보관합니다. 같은 Google 계정을 다른 Caltalk 계정으로 덮어 연결하지 않습니다. 로그아웃 시 해당 브라우저의 계정·기존 역할 쿠키를 제거합니다.

타입 검사, lint, Next.js/Vercel 빌드는 통과했습니다. 실제 가입·메일 수신·캘린더 초대 전체 흐름은 아직 확인하지 않았습니다. 비밀번호 재설정·계정 삭제 UI는 이번 범위에 포함하지 않았습니다.
