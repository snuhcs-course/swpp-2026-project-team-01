근거: `product_requirement_document.md`, `user_stories.md`, `user_flow.md`.

## 2. 첫 진입과 공통 동작

### 2.1 첫 화면과 재진입

| 진입 상태 | 목적지·안내 |
|---|---|
| 실제 이용 모드, 로그인 안 됨 | S9. 로그인 후 원래 목적지를 복원 |
| 신규 사용자, 설정 미시작 | S10에서 연결 또는 건너뛰기. 전체 설정 나중에 하기도 제공 |
| 미완료 초안 있음 | S11에서 이어가기. 재개 시 연결된 일정 갱신 |
| 나중에 하기를 선택한 신규 사용자 | S4에 설정 재개 안내. 요청·수신은 규칙 확정 전 제한 |
| 확정 프로필 또는 기존 규칙 있음 | 원래 목적지, 없으면 S4. 프로필 수정은 S2에서 시작 |
| 연결 해제 후 남은 자료 사용 여부 미선택 | S10의 계속 사용·재연결 선택을 완료하도록 안내. 그 전 요청·수락은 진행하지 않음 |

- 이미 설정한 사용자에게 단순 새로고침만으로 온보딩을 다시 시작시키지 않는다.
- 기존 사용자는 새 프로필을 작성하는 동안 이전 규칙을 사용한다. 신규 사용자에게 미확인 08–22시 기본값을 보여주고 예약을 여는 동작은 없다.
- 실제 이용과 시드 데모는 구분한다. 데모 사용자 전환은 실제 사용자 계정 선택 기능으로 재사용하지 않는다.

### 2.2 화면 공통 상태

- **초안 저장됨**과 **프로필 적용됨**을 구분한다. 초안 자동 저장에 실패하면 저장됐다고 표시하지 않고 현재 입력과 재시도 경로를 유지한다.
- 일정은 **마지막 성공 조회 시각**, 현재 조회 중 여부, 실패 여부를 함께 표시한다. 실패를 빈 목록으로 바꾸지 않는다.
- AI 응답 대기·해석 실패·응답 서비스 장애를 구분한다. 직접 편집 가능한 컨트롤은 장애 안내와 함께 제공한다.
- 진행 중 동작은 중복 실행을 막고 현재 단계를 표시한다. 완료 여부가 불명확한 전송·수락은 상태를 확인한 뒤 재시도하게 한다.
- 규칙과 선호, 일정 출처, 경고는 색뿐 아니라 텍스트·배지로도 구분한다. 입력에는 라벨을 제공하고 오류는 해당 입력과 연결한다.
- 모달·패널은 키보드로 열고 닫을 수 있으며 닫으면 열었던 위치로 돌아간다. 좁은 화면에서도 주요 행동과 직접 편집 경로에 접근할 수 있어야 한다.
- 상대방에게 보이는 정보는 공개 미팅 장소·양식·가능 후보·필요한 추천 근거다. 상대의 개인 일정과 실제 이동 경로 상세를 표시하지 않는다.

## S0. 공통 헤더와 상태 안내

관련 스토리: US-02, US-04, US-06, US-17, US-40. 흐름: F01, F02, F06.

**구성·행동**

- 메뉴: 예약하기(S4), 내 캘린더(S1), 내 미팅 프로필(S2), Calendar 연결(S10), 호스트 설정(S3), 내 요청(S7), 받은 요청함(S8).
- 실제 이용 모드는 본인 계정 표시·로그아웃, 시드 모드는 데모 표시·기존 사용자 전환을 제공한다.
- 설정 미완료이면 `설정 이어가기`를 제공한다. 모든 메뉴 클릭을 반복 팝업으로 가로막지 않는다.
- 받은 대기 요청 수를 표시한다. 날짜·일정 상태는 각 관련 화면에서 확인한다.

**상태·복귀**

- 본인 연결에 재연결이 필요하거나 해제 후 선택이 남아 있으면 S10으로 안내한다.
- 로그인 상태가 끝나면 S9로 이동하며 다른 사용자의 자료를 노출하지 않는다. 재로그인 후 권한을 확인하고 원래 목적지로 복귀한다.

## S1. 내 캘린더

관련 스토리: US-03, US-04, US-05, US-27. 흐름: F02, F04, F11.

**구성·행동**

- 기존처럼 오늘부터 60일을 주 단위로 조회한다. 일정은 KST 시작·종료, 제공된 장소·온라인 정보, 외부/수동/예약 출처를 표시한다.
- 근무시간·미팅 허용 범위·기존 일정을 구분해 보여준다. 근무시간 전체를 바쁜 일정으로 표시하지 않는다.
- 일정 선택 → S13. 외부 일정은 읽기 전용 원본과 앱 내 보완을 구분한다. 수동 일정의 기존 추가·삭제 동작은 유지하고 외부·확정 예약에 삭제 버튼을 제공하지 않는다.
- `일정 새로 가져오기`와 `연결 관리`를 제공한다. 선택한 캘린더와 마지막 성공 조회 시각을 확인할 수 있다. 새로 가져오기는 앞으로 60일의 일정 snapshot만 갱신하고, 실패해도 이미 저장된 일정은 유지한다.
- 외부 일정과 확정 미팅의 새 충돌은 해당 일정에 표시한다. 자세히 보기에서 내 관련 일정을 확인할 수 있다.

**상태·복귀**

- 조회 성공 후 일정이 없으면 빈 상태를 표시한다. 연결 없음이면 앱 내 일정 기준임을 안내한다.
- 갱신 실패는 기존 일정을 유지한 채 실패·재시도 표시. 최초 조회 실패는 가져온 일정이 없다고만 알리고 빈 캘린더 분석 결과로 취급하지 않는다.
- S13을 닫으면 기존 주·선택 위치로 돌아온다. 과거 분석 근거는 S11에서 S13으로 열며 이 화면의 기본 탐색 범위를 과거로 확장하지 않는다.

## S2. 내 미팅 프로필

관련 스토리: US-16, US-19, US-23, US-30, US-40. 흐름: F03, F05.

**구성·행동**

- 현재 확정된 근무시간·미팅 허용 규칙·기본 선호를 주간표와 요약으로 보여준다. 마지막 적용 시각과 작성 중 초안 유무를 표시한다.
- `프로필 수정`은 S11에서 현재 설정을 편집한다. `새 기록으로 제안받기`는 조회 후 S11에 새 제안을 만든다.
- 기존 초안이 있으면 `이어서 수정`으로 진입해 저장한 내용을 복원한다. 재분석만으로 이미 확정한 설정을 덮어쓰지 않는다.
- 현재 기본 프로필과 이번 예약 조건이 별개임을 짧게 설명한다. 예약 대화에서 왔다면 돌아갈 탐색을 유지한다.

**상태·복귀**

- 신규 미설정: `가능 시간 설정 시작` → S10 또는 연결 상태에 따라 S11.
- 기존 규칙만 있음: 해당 규칙을 현재 적용값으로 보여주고 기본 선호는 미설정으로 표시. 새 프로필 확정을 안내한다.
- 허용 구간 없음: `현재 미팅 가능한 시간이 없어요`와 수정 동작. 기본 선호 없음은 정상 상태다.
- 편집을 취소하거나 나갔다 돌아와도 확정값은 유지된다. 새 확정은 S12에서만 수행한다.

## S3. 호스트 설정

관련 스토리: US-12, US-30, US-40. 흐름: F03, F07.

**구성·행동**

- 기존 장소·미팅 양식 추가·수정·삭제를 유지한다. 장소 종류·이름과 양식 이름·길이를 편집한다.
- 상단에 예약 수신 준비 상태를 표시한다: 미팅 허용 규칙 확정 여부, 열린 시간 존재 여부, 장소·양식 등록 여부.
- 시간 규칙 문제는 S2, 장소·양식 문제는 해당 편집 위치로 연결한다. 호스트 선호는 S2의 공통 프로필로 안내한다.

**상태·복귀**

- 장소·양식이 비어 있거나 허용 시간이 없으면 해당 이유를 표시하고 예약 가능하다고 안내하지 않는다.
- 입력·저장 오류는 해당 항목에 표시하고 입력을 유지한다. 온보딩에서 왔다면 설정 완료 후 예약하기 또는 프로필로 이동할 수 있다.

## S4. 호스트 목록

관련 스토리: US-02, US-20, US-21, US-40. 흐름: F01, F07.

**구성·행동**

- 본인을 제외한 호스트 카드에 이름·공개 미팅 장소·양식·예약 가능 상태를 표시한다.
- 예약 가능한 상대 선택 → S5. 같은 상대의 이전 탐색이 있으면 S5에서 이어가기와 새 시작을 선택한다.
- 신규 사용자 미설정이면 상단에 `가능 시간을 먼저 설정해 주세요`와 재개 동작을 제공한다. 설정 후 선택하려던 상대를 복원한다.

**상태·복귀**

- 상대가 장소·양식 미등록 또는 허용 시간 없음이면 예약 불가 이유를 표시한다. 상대 일정의 구체적 내역은 공개하지 않는다.
- 목록 자체가 없으면 빈 상태, 목록 로드 실패이면 재시도를 제공한다. 둘을 구분한다.
- 나중에 하기를 선택한 사용자를 매번 강제 온보딩으로 돌리지 않되 예약 요청·수신 제한은 유지한다.

## S5. 예약 대화

관련 스토리: US-20, US-21, US-22, US-23, US-24, US-25, US-30. 흐름: F07, F08.

**구성**

- 상단: 호스트 이름, 현재 조건에 맞는 후보 수, 자료 갱신 상태. 수집·계산 전에는 후보 수를 0으로 단정하지 않는다.
- 기존 탐색이 있으면 `이어서 찾기`와 `새 미팅 찾기`를 제공한다. 이전 대화를 복원하는 것과 새 탐색 생성은 구분한다.
- 조건 영역: 필수/강/약, `기본 선호`/`이번 예약` 출처를 표시하는 칩. 해제한 기본 선호와 복원 동작을 찾을 수 있게 한다.
- 대화 영역: 실제 계산 근거로 작성한 첫 응답·추가 질문·사용자 발화. 초기 길이 선택은 AI 입력 외에 등록 양식 직접 선택도 제공한다.
- 후보 카드: 최대 3개, 일시·미팅 장소·양식·길이와 필요한 추천 근거. 선택하면 S6.

**핵심 행동**

| 행동 | 반영 범위·화면 결과 |
|---|---|
| 새 미팅 찾기 | 최신 기본 선호 상속, 이전 탐색의 일회성 조건 제외 |
| 이어서 찾기 | 해당 탐색의 상속 기준·명시 조건·해제 상태 유지, 최신 일정으로 재계산 |
| 발화·칩 편집 | 이번 탐색 조건 변경. 기본 프로필은 바뀌지 않음 |
| 기본 선호 해제·복원 | 해제를 다음 턴에도 유지. 복원은 해당 탐색이 상속 중인 기본값 사용 |
| 최신 기본 선호 적용 | 프로필이 바뀐 경우 상속 항목만 갱신, 명시적 변경·해제 유지 |
| 기본 프로필에도 적용 | S11에서 지원하는 항목의 변경 초안 확인. S12 저장 후 같은 탐색으로 복귀 |
| 허용 시간 수정 | 본인의 S2·S11로 이동. 상대 규칙이면 상대 설정이 필요하다는 안내 |

**상태와 문구 기준**

| 상태 | 표시·행동 |
|---|---|
| 첫 후보 준비 | 일정 갱신·조건 계산 중임을 표시. 중복 첫 응답 방지 |
| 양식 미정 | 미팅 길이를 먼저 질문하고 직접 선택 가능. 답변 후 첫 후보 제시 |
| 선호에 맞는 후보 있음 | 적용한 기본 선호와 후보 표시. 호스트 선호는 실제 동점 해소에 사용됐을 때만 설명 |
| 선호 일부 불일치 | 미충족 항목을 밝히고 가능한 대안 제시 |
| 필수 조건으로 0개 | 이유와 조정 동작. 자동 완화하지 않음 |
| 갱신 실패 | 마지막 성공 시각·재시도 표시. 탐색 가능하더라도 요청 단계의 재조회는 생략하지 않음 |
| AI 해석 실패 | 기존 조건 유지, 다시 말하기·직접 조정 안내 |
| 설명 AI 실패 | 계산 결과는 유지하고 템플릿 설명·후보 제공 |
| 기본 선호 없음 | 공통 가능 시간 기준임을 설명. 개인화했다고 표현하지 않음 |

기존 탐색의 재진입은 첫 응답을 새로 삽입하지 않는다. 이전 후보가 화면에 남아 있어도 실제 요청은 S6에서 재검증한다. 프로필 설정을 위해 이동했다 돌아와도 이번 탐색의 명시적 조건을 잃지 않는다.

## S6. 예약 요청 모달

관련 스토리: US-26. 흐름: F09.

- 고정 정보: 호스트·일시·장소·양식. 입력: 메시지 1–500자와 글자 수. 행동: `요청 보내기`, `대화로 돌아가기`.
- 전송 중에는 `일정 확인 중`과 결과를 표시하고 중복 전송을 막는다. 연결된 양쪽의 최신 조회가 실패하면 성공 처리하지 않는다.
- 입력 오류는 해당 입력에서 수정. 조회 실패는 메시지·슬롯을 유지해 재시도. 슬롯 불가·대기 요청 겹침은 이유와 후보 재선택 경로를 제공한다.
- 네트워크 중단으로 결과가 불명확하면 생성 여부를 확인하고, 확인 전 새 요청을 반복 생성하지 않는다.
- 성공하면 `요청을 보냈어요`와 `내 요청 보기` → S7, `닫기` → S5. 수락돼야 앱 내 캘린더에 반영된다는 점을 안내한다.
- 실패 후 S5로 돌아가도 작성 메시지를 보존해 재선택 시 활용한다. 메시지는 확정 전 사용자 입력이며 AI가 임의로 전송하지 않는다.

## S7. 내 요청

관련 스토리: US-26, US-27. 흐름: F09, F11.

- 호스트·일시·미팅 장소·양식·대기/수락/거절/철회/만료를 표시한다. 대기 요청에 기존 `철회` 동작을 제공한다.
- 확정 미팅과 새 외부 일정의 충돌은 당사자에게 표시하고, 내 캘린더(S1)에서 확인하도록 연결한다. 자동 취소·외부 알림을 수행했다고 표시하지 않는다.
- 요청 없음은 빈 상태, 로드 실패는 재시도. 철회 실패 시 서버에서 확인된 상태를 유지한다.
- 수락된 미팅에 취소·변경 버튼을 새로 제공하지 않는다. 내 개인 프로필 변경으로 이전 요청의 조건을 다시 쓰지 않는다.

## S8. 받은 요청함

관련 스토리: US-27, US-31, US-32. 흐름: F10, F11.

- 기존 상태별 목록과 겹치는 대기 요청 묶음을 유지한다. 각 요청에 클라이언트·일시·공개 미팅 장소·양식·메시지를 표시한다.
- 수락 시 자동 거절 영향을 확인하는 영역을 같은 화면에 연다. 재검증 중 영향이 달라졌으면 최신 영향을 다시 확인하게 한다.
- `수락`은 양쪽 미래 일정 재조회와 최신 규칙 검증 후 완료한다. `거절`은 조회 성공을 기다릴 필요 없이 기존 권한·요청 상태를 검사한다.
- 조회 실패·슬롯 불가·철회됨·이미 처리됨·만료를 구분해서 표시한다. 실패한 수락은 대기 요청을 자동 거절하지 않으며 재시도·거절 경로를 남긴다.
- 성공 시 수락 상태와 겹치는 요청의 거절 상태를 갱신한다. 확정 일정은 앱 내 캘린더에 반영되며 외부 캘린더 쓰기를 암시하지 않는다.
- 빈 목록과 로드 실패를 구분한다. 확정 충돌은 당사자 화면에서 확인하되 상대의 사적 일정 내역은 표시하지 않는다.

## S9. 로그인

관련 스토리: US-01, US-02, US-40. 흐름: F01.

- 실제 이용 모드에서 Google 계정으로 사용자 확인을 시작한다. 이메일·비밀번호 입력이나 별도 회원가입 양식은 추가하지 않는다.
- 로그인과 캘린더 읽기 권한 연결이 별도 단계임을 설명한다. 로그인 후 S10에서 캘린더 연결을 건너뛸 수 있다.
- 처리 중·취소·실패를 표시하고 재시도를 제공한다. 확인되지 않은 사용자의 초안이나 일정을 표시하지 않는다.
- 성공하면 신규는 연결·설정, 기존 사용자는 원래 목적지로 이동한다. 시드 데모는 실제 계정의 대체 로그인으로 표시하지 않는다.

## S10. Calendar 연결·관리

관련 스토리: US-01, US-02, US-04, US-06. 흐름: F01, F02, F06.

**구성·입력**

- 본인 연결 계정, 연결 상태, 캘린더 선택 목록, 과거 8주 분석·미래 60일 계산 안내, 분석에 사용하는 정보 범위.
- 최초 연결은 `Google Calendar 연결` → 읽기 권한 요청 → 사용할 캘린더 선택 → `선택한 일정 가져오기` 순서다.
- 최초 설정에서는 `연결 없이 직접 설정` → S11과 `나중에 하기` → S4를 제공한다. 로그인 자체를 생략하는 동작은 아니다.
- 이미 연결된 경우 선택 캘린더 수정, 새로 가져오기, 재연결, 연결 해제를 제공한다. 캘린더별 조회 상태와 마지막 성공 조회 시각을 확인할 수 있다.

**상태·전환**

| 상태 | 행동과 목적지 |
|---|---|
| 캘린더 미선택 | 가져오기 완료로 처리하지 않음. 선택 또는 연결 없이 설정 |
| 권한 취소·거절 | 다시 연결 또는 직접 설정. 기존 자기 초안 유지 |
| 최초 조회 중 | 수집 진행 표시. 임의의 성공률·예상 시간을 만들지 않음 |
| 성공, 일정 있음 또는 실제로 없음 | 결과 구분 후 최초 설정은 S11, 관리에서 왔다면 원래 목적지 |
| 일부 또는 전체 실패 | 마지막 성공 자료 유지, 재시도. 직접 초안 편집은 가능 |
| 재연결 필요 | 계정 소유자에게 재연결 동작. 실패 상태를 연결 안 함으로 바꾸지 않음 |
| 연결 해제·선택 해제 | 제거 범위와 유지할 정보를 확인한 뒤 실행. 원본 캘린더는 수정하지 않음 |
| 해제 후 이용 방식 미선택 | `남은 일정으로 계속 사용` 또는 `다시 연결`. 선택 전 요청·수락 제한 |

해제 시 확정 프로필·앱 내 일정은 유지된다고 안내하고, 외부 일정이 빠져 가능한 시간이 늘 수 있음을 설명한다. 모든 선택 해제를 실수로 빈 일정 수집 성공으로 처리하지 않는다. 분석 근거에서 제거된 자료를 현재 근거로 다시 표시하지 않는다.

## S11. 프로필 설정 작업 화면

관련 스토리: US-10, US-11, US-12, US-13, US-14, US-15, US-17, US-18, US-19, US-22. 흐름: F03, F05.

**화면 구성**

- 상단: `처음 설정` 또는 `프로필 수정`, 근무시간·미팅 허용 시간·기본 선호의 확인 상태, 초안 저장 상태.
- 넓은 화면: 한쪽에 대화·제안, 다른 쪽에 주간표·직접 편집·설정 요약을 나란히 배치한다.
- 좁은 화면: `대화`와 `시간표·설정`을 전환하되 같은 초안을 사용한다. 입력과 `최종 확인` 동작을 찾을 수 있게 유지한다.
- 최초·기존 규칙 전환·프로필 수정·재분석·예약 중 기본값 변경은 같은 편집 화면을 사용하고 진입 이유를 표시한다.

**대화·제안 영역**

- AI 질문, 근거가 붙은 제안, 사용자 답변, 입력창·전송, `직접 설정` 진입점.
- 제안에는 관찰한 기간·빈도와 추정/확인된 정보를 구분하고 `근거 보기` → 본인 일정의 S13을 제공한다.
- 근거가 없으면 직접 질문한다. 한 발화의 여러 주제 답변을 모두 반영하고 완료한 질문을 반복하지 않는다.
- 사용자가 제안을 선택·수정하면 초안과 주간표를 갱신한다. 대화가 완료됐다는 이유만으로 확정 프로필을 저장하지 않는다.

**직접 편집 영역**

| 주제 | 입력·선택 | 표시·검증 |
|---|---|---|
| 근무시간 | 요일별 시작·종료와 구간 추가/삭제, 고정 패턴 없음 | 미팅 허용 시간이나 회사 일정과 구분 |
| 미팅 허용 시간 | 요일별 복수 구간, 요일 닫기, 전체 미팅 받지 않음 | 미팅 전체가 들어가야 함. 신규 기본값 자동 개방 없음 |
| 기본 선호 | 요일 집합, 시작 시간대 하나, 온라인/오프라인, 앞뒤 여유 | 항목별 강/약/없음. 특정 호스트 장소·양식은 포함하지 않음 |

- 자정 넘김은 두 요일로 나뉜 결과를 확인시킨다. 겹치는 구간은 합친 결과를 보여준다.
- 잘못된 시간 구간·허용 시간과 선호의 충돌은 관련 입력에서 수정한다. 지원하지 않는 날짜별 예외·방식별 허용·필수 여유는 제한을 설명한다.
- 근무시간을 수정해도 허용 시간은 자동 변경하지 않는다. 기록 재분석은 제안으로 표시하고 사용자 확정값을 덮어쓰지 않는다.

**행동·실패·복귀**

- `최종 확인` → S12. 미확인 주제·충돌이 있으면 해당 위치를 안내한다. '없음'으로 답한 주제는 완료로 취급한다.
- `나중에 이어하기` 또는 이전 화면으로 돌아가면 마지막 저장 초안부터 재개할 수 있다. 아직 저장되지 않은 입력이 있으면 저장 실패·재시도 상태를 알린다.
- AI 실패 중에도 직접 편집과 최종 확인이 가능하다. 서비스 실패와 해석 실패를 구분하고 마지막 유효 초안을 유지한다.
- S13에서 분류·장소 보완 후 닫으면 같은 주제·대화로 복귀한다. 모든 일정을 보완해야 최종 확인이 열리도록 만들지 않는다.

## S12. 프로필 최종 확인

관련 스토리: US-15, US-16, US-19, US-23. 흐름: F03, F05.

- 주간표와 세 주제의 최종 요약을 함께 보여준다. 수정·재분석이면 현재 확정값에서 바뀌는 부분도 표시한다.
- 각 주제의 `수정` → S11의 해당 입력. `프로필 적용`은 검증 후 전체를 새 버전으로 확정한다.
- 적용 전에는 초안임을 명시한다. 저장 중 중복 클릭을 막고 실패하면 초안과 이전 확정값을 유지해 재시도한다.
- 허용 시간 없음은 '예약 불가 상태로 저장'임을 알리고 유효한 선택으로 처리한다. 선호 없음·고정 근무 없음도 오류로 표시하지 않는다.
- 저장 성공 후 완료 영역에서 `예약 찾기` → S4, `호스트 설정` → S3, `내 프로필 보기` → S2 중 진입 목적에 맞는 동작을 제시한다. 예약 대화에서 왔다면 `예약으로 돌아가기` → 같은 S5 탐색을 우선한다.
- 새 허용 규칙은 이후 계산에 적용되고 새 선호는 새 탐색의 기본값이 된다는 점을 설명한다. 진행 중 탐색의 상속 선호 변경은 S5의 명시적 적용 동작으로 구분한다.

## S13. 일정·분석 근거 상세 패널

관련 스토리: US-03, US-05, US-10, US-11, US-12, US-13. 흐름: F02, F03, F04.

- 내 캘린더의 일정 선택 또는 온보딩 `근거 보기`에서 연다. 소유자 본인의 수집·앱 내 일정만 표시한다.
- 일정 제목·시작·종료·출처·바쁨 여부·제공된 장소·온라인 단서와, 사용자 보완 정보를 구분한다. 읽을 수 없는 정보는 미확인으로 표시한다.
- 분석 근거로 열면 사용한 기간·집계·관련 기록을 함께 보여주고 업무/개인/미확인과 업무 미팅 여부를 확인·수정할 수 있게 한다. 집중 시간·부재 등을 미팅 빈도에 포함하지 않는 기준은 유지한다.
- 장소 보완은 회사·특정 장소·온라인 정보와 확인 상태를 다룬다. 원본 장소와 화상회의 링크가 함께 있어도 참석 방식을 자동 확정하지 않는다.
- `보완 저장`은 앱 내 해석만 갱신하며 외부 원본을 수정하지 않는다. 원본 정보 변경으로 재확인이 필요하면 이전 보완을 함께 보여준다.
- 실패하면 입력을 유지한다. 저장·닫기 후 호출한 S1의 주·선택 위치 또는 S11의 주제·대화 위치로 복귀한다.
- 제거된 출처·접근 불가 자료는 현재 확인 가능한 근거로 표시하지 않는다. 출처 상태를 설명하고 필요한 연결 관리 동작을 제공한다.

## 4. 기존 화면에서 바뀌는 책임과 다음 문서

- S2는 확정 프로필의 조회·편집 진입을 담당하고, 편집·최종 적용은 S11·S12로 모은다. 요일 규칙을 별도로 즉시 저장하는 두 번째 경로를 남기지 않는다.
- S1은 일정 조회·수동 일정 관리를 유지한다. 프로필 시간표는 S11에서 같은 정보 구분을 사용하되 초안을 편집한다.
- S5는 상대별 대화뿐 아니라 이번 탐색과 기본 프로필 적용 범위를 표시한다. 탐색을 식별하는 실제 URL·저장 방식은 아키텍처에서 정한다.
- S10은 최초 연결과 이후 연결 관리를 공용으로 사용한다. 초기 연결만 별도 일회성 화면으로 구현하지 않는다.
