# User Stories — AI 온보딩과 개인 미팅 프로필

작성일: 2026-10-04 · 상태: 확정 (2026-10-04 검토 완료) · 근거: `product_requirement_document.md`

형식: **[역할]으로서, [목표]하고 싶다. 그래야 [이유].** 각 스토리의 확인 기준은 사용자에게 나타나는 결과를 설명한다. FR·NFR·AC 번호는 이 폴더의 PRD를 참조하며 기존 MVP 문서의 번호와 구분한다.

이 문서는 확정된 PRD를 사용자 관점으로 풀어쓴다. 화면 배치와 API 설계, 새로운 기능 범위는 결정하지 않는다. 아래 예시 발화와 일정은 가상 데이터다.

---

## 1. 공통 — 캘린더 연결과 일정 확인

**US-01 내 캘린더를 연결하고 사용할 자료 선택하기** (FR-01, FR-03, FR-04, FR-10, FR-11; NFR-04, NFR-05; AC-01)

신규 사용자로서, 내 Google 계정에 있는 캘린더 중 사용할 것을 선택하고 싶다. 그래야 실제 일정을 바탕으로 미팅 가능 시간을 설정할 수 있다.

- 연결 전에 과거 8주는 패턴 분석, 오늘부터 60일은 예약 계산에 사용한다는 안내와 외부 AI 분석에 쓰이는 데이터 범위를 확인한다.
- 사용자당 계정 하나에서 여러 캘린더를 선택할 수 있다. 선택하지 않은 캘린더의 일정은 가져오지 않는다.
- 연동은 읽기 전용이다. 완료 후 내 일정이 표시되고 AI 설정 세션이 시작된다.
- 내 연결·초안·프로필·수집 일정은 다른 실제 사용자가 조회하거나 수정할 수 없다.

**US-02 연결 없이 직접 시작하거나 나중에 설정하기** (FR-02, FR-06, FR-07, FR-18; AC-05)

신규 사용자로서, 캘린더 연결을 건너뛰거나 설정을 미루고 싶다. 그래야 지금 제공할 수 있는 정보만으로 시작할 수 있다.

- 연결을 취소해도 직접 미팅 허용 시간을 설정할 수 있고, 전체 설정을 미루면 나중에 재개할 수 있다.
- 미팅 허용 규칙을 확정하기 전에는 예약 요청·수신이 열리지 않는다. 확인하지 않은 08–22시가 자동 적용되지 않는다.
- 연결 없이 완료한 경우 앱에 등록된 일정 기준으로 후보를 계산한다는 점을 확인할 수 있다.
- 근무 패턴이나 선호가 없어도 완료할 수 있다. 허용 시간을 모두 닫아 저장하면 예약 불가로 표시된다.

**US-03 가져온 일정의 시간과 상태 확인하기** (FR-11, FR-12, FR-13, FR-14, FR-15; NFR-01; AC-01, AC-02, AC-10)

사용자로서, 가져온 일정이 실제로 어느 시간을 막는지 확인하고 싶다. 그래야 앱이 계산한 가능 시간을 이해할 수 있다.

- 시각이 있는 일정은 KST로 표시되고 시작·종료·제공된 장소와 온라인 정보가 유지된다.
- 반복 일정은 변경·취소된 회차가 반영되고, 같은 회차를 다시 가져와도 중복으로 나타나지 않는다.
- 바쁜 종일 일정은 해당 날짜를 막는다. 취소·참석 거절·비차단 일정은 미팅 시간을 막지 않고 미응답·참석 미정 초대는 막는다.
- 업무 위치 정보만으로 종일 바쁘게 만들지 않는다. 집중 시간·부재는 바쁨 상태를 따른다.
- 제목·장소를 읽을 수 없어도 바쁜 구간은 남아 있다. 종일 일정이나 업무 위치 정보를 실제 이동의 출발점으로 취급하지 않는다.

**US-04 변경된 일정 가져오기와 실패 확인하기** (FR-04, FR-12, FR-16, FR-17; AC-02)

사용자로서, 바뀐 외부 일정을 다시 가져오고 최신 상태인지 알고 싶다. 그래야 오래된 자료를 믿고 예약하지 않는다.

- 수동 새로 가져오기가 가능하고 온보딩 재개·새 예약 탐색·예약 화면 재진입에서도 갱신한다.
- 성공하면 변경·삭제가 반영되고 마지막 성공 조회 시각이 바뀐다. 조회 범위도 현재 날짜에 맞춰 이동한다.
- 일부 조회가 실패하면 마지막 성공 자료를 유지하고 실패를 알린다. 실패를 일정이 사라진 것으로 처리하지 않는다.
- 재시도·중복 클릭으로 일정이 중복되거나 새 첫 응답이 여러 개 생기지 않는다.

**US-05 일정의 장소와 참석 방식 보완하기** (FR-25, FR-26, FR-27; AC-10)

사용자로서, 일정이 어디에서 끝나는지와 온라인 참석 여부를 확인하고 수정하고 싶다. 그래야 다음 미팅의 이동 조건이 내 상황에 맞게 계산된다.

- 장소가 미확인인지 확인된 정보인지 구분할 수 있다. 장소와 화상회의 링크가 함께 있어도 온라인 참석으로 확정하지 않는다.
- 미확인 장소에는 기존 '장소 없음' 이동 규칙이 적용되고, 정확한 실제 이동시간이라고 설명하지 않는다.
- 내가 보완한 정보는 단순 재조회로 지워지지 않는다. 원본 장소·온라인 정보가 바뀌면 보완 내용을 다시 확인한다.
- 근무시간을 입력했다고 회사에 있는 일정이 만들어지지 않는다. 일정 종료 장소를 이후 계속 머무를 위치라고 설명하지 않는다.

**US-06 캘린더 선택 또는 연결 해제하기** (FR-19; AC-12)

사용자로서, 더 이상 사용하지 않을 캘린더의 연결을 해제하고 싶다. 그래야 사용할 일정 자료를 내가 관리할 수 있다.

- 선택 해제한 출처의 일정·분석 근거는 제거되고 추가 조회가 중단된다.
- 확정한 프로필과 앱 내 수동·예약 일정은 유지된다.
- 외부 일정이 빠져 가능 시간이 늘 수 있음을 안내받고, 남은 자료 기준으로 계속 사용할지 다시 연결할지 선택한다.

## 2. 공통 — AI와 개인 미팅 프로필 만들기

**US-10 내 기록을 근거로 한 질문 받기** (FR-20, FR-21, FR-23, FR-24; NFR-03; AC-03, AC-05)

사용자로서, AI가 내 기록에서 무엇을 보고 제안했는지 알고 싶다. 그래야 제안이 내 실제 생활을 반영하는지 판단할 수 있다.

- 제안에 사용한 기간·횟수·일정 근거를 확인할 수 있고, AI 추정과 내가 확인한 분류가 구분된다.
- 업무·개인 분류를 바로잡을 수 있으며, 업무 일정 전체를 미팅 횟수로 세지 않는다.
- 기록이 없거나 단서가 부족하면 직접 질문받는다. 근거가 적으면 그 범위를 밝히고 개인화된 확신처럼 표현하지 않는다.
- 근무·미팅·선호에 이미 답한 내용은 다음 질문에 반영된다.

**US-11 일하는 시간 확인하기** (FR-22, FR-27, FR-30, FR-32, FR-33; AC-03, AC-04)

사용자로서, AI가 제안한 근무시간을 내 실제 패턴에 맞게 고르고 싶다. 그래야 이후 미팅 허용 시간을 쉽게 정할 수 있다.

- 개인 약속 시작은 근무 종료의 단서로만 제시되고 근무 시작은 별도로 확인한다.
- 요일마다 다른 근무시간과 하루 여러 구간을 입력할 수 있고, 고정 패턴이 없다고 답할 수도 있다.
- 근무시간 전체가 바쁜 일정이나 미팅 허용 시간으로 자동 변환되지 않는다.
- 근무시간을 나중에 바꿔도 이미 정한 미팅 허용 시간은 자동으로 바뀌지 않는다.

**US-12 미팅을 받을 시간 따로 정하기** (FR-07, FR-22, FR-30, FR-32, FR-33; AC-03, AC-04)

사용자로서, 일하는 시간 중 또는 그 밖에서 미팅에 쓸 구간을 직접 정하고 싶다. 그래야 집중 업무나 개인 시간을 보호할 수 있다.

- 늦은 업무 미팅이 있었다면 평소 가능한 시간인지 예외였는지 확인한다. 가장 늦었던 한 건이 허용 종료 시각으로 자동 설정되지 않는다.
- 예를 들어 화·목 10–12시와 14–18시를 열면 점심을 가로지르는 미팅은 후보에서 제외된다.
- 요일을 통째로 닫거나 근무시간 밖을 열 수 있다. 자정을 넘는 구간은 두 요일로 나누어 확인한다.
- 호스트로 예약을 받으려면 허용 시간 외에 장소·미팅 양식 등록도 필요하다는 것을 알 수 있다.

**US-13 자주 잡힌 시간과 원하는 시간 구분하기** (FR-23, FR-30, FR-34, FR-35; AC-03, AC-04)

사용자로서, 자주 미팅을 잡았던 시간이 앞으로도 좋은 시간인지 선택하고 싶다. 그래야 과거 사정에 끌려가지 않고 내 선호를 저장할 수 있다.

- “화·목 오후에 미팅이 자주 있었어요. 앞으로도 우선 추천할까요?”처럼 관찰과 선호 확인을 구분한다.
- 요일, 시작 시간대 하나, 온라인/오프라인, 앞뒤 여유를 강하게·약하게 선호하거나 선호 없음으로 설정한다.
- 선호 시간대는 미팅 시작 시각에 적용되고 미팅 허용 구간은 전체 길이에 적용된다는 것을 확인할 수 있다.
- 특정 호스트의 장소·양식이나 일회성 날짜는 공통 기본 선호로 저장되지 않는다.

**US-14 한 번에 말하고 주간표에서 고치기** (FR-30, FR-31; AC-04)

사용자로서, 근무시간과 미팅 규칙을 한 번에 설명하고 직접 편집도 하고 싶다. 그래야 질문을 반복해서 답하거나 AI를 다시 설득하지 않아도 된다.

- “평일 9–18시 근무, 화·목 오후만 미팅, 가능하면 온라인”을 말하면 세 주제에 각각 반영된다.
- 주간표와 요약에서 기존 일정·근무시간·미팅 허용 시간·선호를 구분한다.
- 직접 수정한 내용과 대화에서 수정한 내용은 같은 초안에 반영되고, 앞선 주제로 돌아갈 수 있다.

**US-15 충돌하거나 지원하지 않는 설정 알아보기** (FR-32, FR-33, FR-35, FR-36; AC-04)

사용자로서, 입력한 설정이 서로 충돌하거나 지금 지원되지 않으면 알고 싶다. 그래야 내 의도와 다른 규칙을 저장하지 않는다.

- 종료가 시작보다 빠른 구간은 수정 안내를 받고, 겹치는 구간은 합쳐진 결과를 확인한다.
- 오전만 허용했는데 오후만 선호하면 저장 전에 충돌을 확인하고 수정한다.
- “이번 목요일만 제외”, “저녁에는 온라인만”, “반드시 30분 비우기”는 첫 버전에서 지원하지 않는다고 안내받는다. 다른 의미의 선호로 몰래 저장되지 않는다.
- 선호 없음·고정 근무 없음·미팅을 받지 않음은 오류로 취급하지 않는다.

**US-16 최종 결과를 확인하고 저장하기** (FR-06, FR-07, FR-37; NFR-07; AC-04, AC-05)

사용자로서, AI와 정리한 결과를 확인한 뒤 프로필을 확정하고 싶다. 그래야 내가 동의한 설정만 예약에 적용된다.

- 근무시간·미팅 허용 규칙·기본 선호를 함께 확인하고 저장한다. AI가 답했다고 확정되지 않는다.
- 저장은 전체 결과에 대해 적용되고 실패하면 이전 확정 상태를 유지한다.
- 신규 사용자는 확정 전 예약이 열리지 않고, 기존 사용자가 새 초안을 편집하는 동안에는 이전 규칙이 적용된다.

**US-17 중단한 대화를 이어서 설정하기** (FR-02, FR-05; NFR-07; AC-05)

사용자로서, 설정 중 나갔다 돌아와도 이어서 진행하고 싶다. 그래야 긴 대화를 처음부터 반복하지 않는다.

- 마지막으로 저장된 초안과 진행 내용을 복원한다.
- 중복 전송이나 새로고침으로 같은 답변이 여러 번 적용되거나 프로필이 확정되지 않는다.
- 나중에 하기를 선택하면 다시 시작할 위치를 찾을 수 있다.

**US-18 AI가 실패해도 직접 완료하기** (FR-24, FR-31, FR-38; NFR-02, NFR-03; AC-05)

사용자로서, AI 응답이 없거나 내 말을 해석하지 못해도 설정을 완료하고 싶다. 그래야 서비스 상태 때문에 온보딩이 막히지 않는다.

- 대기 중인지 실패했는지 알 수 있고 재시도하거나 직접 편집할 수 있다.
- 실패한 응답은 마지막 유효 초안을 바꾸지 않고 성공으로 표시되지 않는다.
- 직접 설정한 결과도 같은 최종 확인과 저장 과정을 거친다.

**US-19 저장한 프로필 수정하고 다시 분석하기** (FR-37, FR-38, FR-41, FR-62, FR-63; AC-07, AC-12)

사용자로서, 생활 패턴이 바뀌면 프로필을 수정하거나 새 기록으로 제안받고 싶다. 그래야 앞으로의 예약이 현재 생활에 맞게 바뀐다.

- 재분석은 초안을 만들고 기존 사용자 설정을 자동 덮어쓰지 않는다.
- 저장한 선호는 새 탐색의 기본값이 된다. 진행 중 탐색은 최신 기본 선호 적용을 선택할 수 있다.
- 미팅 허용 규칙 변경은 이후 후보 재계산에 반영되지만 기존 대기 요청이나 확정 미팅을 자동 삭제하지 않는다.

## 3. 클라이언트 — 개인화된 예약 시작과 조정

**US-20 기본 선호로 첫 후보 받기** (FR-40, FR-45, FR-55, FR-56; AC-06)

클라이언트로서, 상대를 고르면 내 기본 선호에 맞춘 선택지부터 보고 싶다. 그래야 매번 내 선호를 다시 설명하지 않아도 된다.

- “기본 선호인 화·목 오후를 기준으로 가능한 시간을 살펴봤어요”처럼 실제 적용한 조건을 설명한다.
- 미팅 양식이 하나거나 정해졌으면 후보가 존재할 때 최대 3개를 제시한다. 여러 양식 중 길이가 미정이면 먼저 질문한다.
- 후보는 양쪽이 가능한 시간이며 서로 다른 시간대를 제시하는 기존 다양화 규칙을 따른다.
- 기본 선호가 없으면 선호를 적용한 것처럼 설명하지 않는다.

**US-21 같은 상대와 이어가기 또는 새로 시작하기** (FR-40, FR-41; AC-06, AC-07)

클라이언트로서, 같은 상대와 기존 대화를 이어가거나 새로운 미팅을 찾고 싶다. 그래야 이전 예약의 예외가 다음 예약까지 남지 않는다.

- 기존 탐색을 이어가면 그 탐색의 조건과 시작 당시 기본 선호를 유지한다.
- 새 미팅 찾기는 현재 기본 선호로 시작하고 이전 탐색의 일회성 변경·해제를 가져오지 않는다.
- 어느 경우에도 후보는 최신 확정 허용 규칙과 현재 수집 일정을 기준으로 다시 계산한다.

**US-22 이번 예약에서만 선호 바꾸거나 해제하기** (FR-42, FR-43; AC-07)

클라이언트로서, “이번에는 오전도 괜찮아”처럼 이번 미팅의 조건만 바꾸고 싶다. 그래야 평소 선호를 유지하면서 예외를 찾을 수 있다.

- 언급한 항목은 대체되고 다른 기본 선호는 유지된다. 칩에 기본 선호인지 이번 예약 조건인지 표시된다.
- 칩을 해제하면 다음 턴에도 해제 상태가 유지되고, 원하면 기본값으로 복원한다.
- 이 변경으로 프로필이 수정되지 않는다. “앞으로도 이렇게”라고 하면 프로필 변경 초안을 확인하고 저장한다.

**US-23 진행 중 예약에 최신 선호 적용하기** (FR-41, FR-43; AC-07)

클라이언트로서, 프로필을 바꾼 뒤 진행 중인 탐색에 적용할지 선택하고 싶다. 그래야 대화 중에 조건이 갑자기 달라지지 않는다.

- 기본 선호를 수정해도 진행 중 탐색의 선호는 자동 대체되지 않는다.
- 최신 기본 선호 적용을 선택하면 상속한 항목만 갱신하고, 이번 탐색에서 명시적으로 변경·해제한 항목은 보존한다.
- 미팅 허용 규칙의 최신 상태는 이 선택과 무관하게 후보 계산에 적용된다.

**US-24 내가 원하는 순서로 추천받고 이유 이해하기** (FR-47, FR-50, FR-51, FR-52, FR-53, FR-54, FR-55, FR-56; AC-08)

클라이언트로서, 내 조건이 우선되면서 상대도 선호하는 시간을 추천받고 싶다. 그래야 추천을 이해하고 선택할 수 있다.

- 양쪽 필수 조건을 통과한 후보 중 내 선호 점수가 높은 후보가 먼저 나온다. 내 점수가 같을 때 호스트 선호가 순위에 반영된다.
- “빠른 순”, “늦은 순”을 명시하면 같은 내 선호 점수 안에서 가까운 날짜와 요청한 시각 순서가 호스트 선호보다 먼저 적용된다.
- 같은 조건·자료로 계산하면 같은 순서가 나오고, 다양화를 위한 후보 선택도 설명과 일치한다.
- 추천 이유에는 실제 적용한 조건만 나타나며 상대의 사적 일정·위치 상세를 노출하지 않는다.

**US-25 맞는 시간이 없으면 조정 방법 알기** (FR-44, FR-46, FR-50, FR-56; AC-09)

클라이언트로서, 원하는 시간이 없으면 무엇을 바꿀 수 있는지 알고 싶다. 그래야 불가능한 조건으로 대화를 반복하지 않는다.

- 선호만 충족하지 못하면 어떤 선호가 맞지 않는지 설명하고 가능한 대안을 보여준다.
- 필수 조건 때문에 0개이면 후보를 지어내거나 자동으로 조건을 풀지 않는다.
- 미팅 허용 범위를 바꿔야 한다면 해당 사용자의 프로필 편집이 필요하다고 안내한다. 내 선호 변경으로 상대 허용 시간을 넓힐 수 없다.

**US-26 요청 직전에 최신 가능 여부 확인받기** (FR-18, FR-50, FR-62; AC-11)

클라이언트로서, 선택 이후 일정이 바뀌었으면 요청을 보내기 전에 알고 싶다. 그래야 이미 불가능해진 시간으로 요청하지 않는다.

- 연결된 양쪽의 미래 일정을 다시 조회하고 현재 허용 규칙과 충돌을 검사한다.
- 충돌하면 요청을 만들지 않고 이유를 안내한다. 필요한 조회가 실패해도 전송 완료로 표시하지 않는다.
- 연동하지 않은 사람의 일정은 앱에 등록된 자료 기준으로 확인한다.
- 요청 메시지 작성과 기존 겹치는 대기 요청 방지 규칙은 유지된다.

**US-27 확정 미팅이 새 일정과 겹쳤는지 확인하기** (FR-62, FR-63; AC-12)

예약 당사자로서, 새 외부 일정이 확정 미팅과 겹치면 알고 싶다. 그래야 기존 약속을 확인하고 대응할 수 있다.

- 갱신으로 발견한 충돌은 당사자 화면에서 확인할 수 있다.
- 기본 선호·허용 규칙 변경이나 새 충돌 때문에 확정 미팅이 자동 삭제·취소되지 않는다.
- 첫 버전에서 제공하지 않는 확정 예약 변경·취소나 외부 알림을 수행한 것처럼 표시하지 않는다.

## 4. 호스트 — 기본 선호 반영과 요청 처리

**US-30 내 선호도 추천에 반영하기** (FR-34, FR-47, FR-51, FR-52, FR-53, FR-54; AC-08)

호스트로서, 클라이언트에게 비슷하게 좋은 시간이라면 내가 선호하는 시간을 먼저 추천하고 싶다. 그래야 별도로 조율하지 않아도 내 선호가 활용된다.

- 클라이언트 점수가 같고 명시적 시간 순서도 충돌하지 않는 후보에서만 호스트 선호가 작용한다.
- 예를 들어 클라이언트가 화·목 오후를 똑같이 선호하고 나는 목요일을 선호하면 목요일 후보가 먼저 나온다.
- 내 선호 수정은 이후 탐색 재계산에 반영되지만 클라이언트의 조건 자체를 바꾸지 않는다.
- 미팅 금지 시간은 동점 해소가 아니라 필수 조건으로 적용된다.

**US-31 수락 전에 바뀐 일정 재검증하기** (FR-18, FR-62, FR-63; AC-11, AC-12)

호스트로서, 대기 요청을 수락할 때 지금도 가능한지 확인하고 싶다. 그래야 요청 이후 추가된 일정과 겹치지 않는다.

- 수락 직전 연결된 양쪽 일정을 새로 조회하고 최신 허용 규칙으로 검증한다.
- 불가능하거나 조회에 실패하면 수락을 완료하지 않는다. 선호만 바뀐 것은 수락 불가 사유가 되지 않는다.
- 수락하면 기존처럼 양쪽 앱 캘린더에 반영하고 겹치는 다른 대기 요청을 자동 거절한다.
- 외부 Google 캘린더에는 확정 미팅을 썼다고 표시하지 않는다.

**US-32 프로필을 바꿔도 받은 요청 유지하기** (FR-62, FR-63; AC-12)

호스트로서, 미팅 규칙을 바꾼 뒤에도 이미 받은 요청을 확인하고 싶다. 그래야 기존 요청을 내가 판단해 처리할 수 있다.

- 허용 규칙 변경만으로 대기 요청을 자동 거절하지 않는다. 수락 시점에 새 규칙으로 다시 검증한다.
- 기본 선호 변경은 대기·확정 상태를 바꾸지 않는다.
- 기존 요청 확인·거절·클라이언트 철회 흐름은 유지된다.

## 5. 기존 MVP 사용자와 데모

**US-40 기존 설정과 데모 흐름 유지하기** (FR-06, FR-60, FR-61; NFR-06; AC-04, AC-06)

기존 MVP 사용자로서, 저장한 가능 시간과 대화를 유지하면서 새 기능을 사용하고 싶다. 그래야 온보딩을 추가했다고 기존 작업이 사라지지 않는다.

- 기존 요일별 구간은 의미를 바꾸지 않고 새 표현으로 옮겨지고, 새 프로필 확정 전에도 기존 규칙을 유지한다.
- 기존 사용자의 선호는 임의로 생성하지 않는다. 기존 대화 조건은 해당 탐색의 명시적 조건으로 유지한다.
- 사용자 전환을 통한 시드 데모는 실제 계정 연결과 구분되며, 실제 계정에 시드 일정·데모 인물이 복사되지 않는다.
- 시드로 시연한 결과와 실제 계정 연결로 검증한 결과를 구분한다.

## 7. 범위 밖과 다음 문서

외부 캘린더 쓰기·실시간 푸시 동기화·다른 공급자, 실제 경로 조회, 날짜별 예외·방식별 허용 시간·필수 최소 여유, 프로필 자동 변경, 확정 예약 취소·변경·알림은 이번 스토리에 추가하지 않는다.

성능·토큰 관리·외부 텍스트 취급 등 공통 비기능 요구사항은 PRD를 그대로 따른다. 다음 `user_flow.md`에서는 이 스토리들을 연결·초안·확정·탐색·요청 상태 사이의 이동과 실패 후 복귀 흐름으로 연결한다.
