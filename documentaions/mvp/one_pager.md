# One Pager — AI 미팅 예약 (가칭)

> **One-liner**: 두 사람의 캘린더와 이동시간으로 "실제로 만날 수 있는 시간"을 계산해두고, 클라이언트가 자연어 대화로 원하는 시간을 좁혀 호스트에게 예약을 요청하는 웹 앱.

작성일: 2026-09-29 · 상태: 확정 (2026-09-29 검토 완료)

---

## 1. 문제

Calendly류 도구는 호스트의 빈 시간만 보여준다. 클라이언트는 자기 일정과 **장소 간 이동시간**을 머릿속으로 맞춰가며 고르고, "다음 주 평일 오후, 가능하면 온라인" 같은 선호를 슬롯 목록에서 직접 찾아야 한다.

## 2. 해결

1. 앱이 호스트·클라이언트 캘린더, 가능 시간 규칙, 장소별 이동시간을 반영해 **오늘부터 60일간 (시간, 장소, 미팅 양식) 슬롯**을 결정적으로 계산한다.
2. 클라이언트는 AI와 **대화**한다. AI는 대화에서 선호를 뽑아 **필터(반드시 조건 + 선호 가중치)**를 만들고 고친다.
3. 코드가 필터로 슬롯을 지우고 점수를 매겨 순위를 낸다. AI는 결과 요약을 보고 설명하거나 되묻는다.
4. 조건이 충족되면 상위 **최대 3개**를 버튼으로 보여준다. 클라이언트가 누르고 **메시지를 직접 써서** 요청한다.
5. 호스트는 요청을 보고 **수락/거절**한다.

**AI는 슬롯을 고르거나 만들지 않는다.** 선호를 뽑아 필터로 만들고, 결과를 해석해서 대화를 이끄는 역할만 한다. 가능 여부 판정과 순위는 항상 코드가 한다.

## 3. 사용자

- **호스트**: 자기 캘린더, 가능 시간 규칙, 장소, 미팅 양식을 등록하고 예약 요청을 수락/거절한다.
- **클라이언트**: 자기 캘린더를 등록하고, 대화로 시간을 찾아 요청을 보낸다.
- 한 사람이 양쪽 역할을 모두 할 수 있다. MVP의 주 사용자는 **웹 사용자**다. 외부 에이전트가 쓰는 블록 인터페이스는 이후 확장.

## 4. 핵심 규칙

### 4.1 가능 시간
- 사람마다 주간 규칙이 있다. 기본값은 **매일 08:00–22:00**이고 사용자가 바꿀 수 있다. 규칙 밖 시간은 바쁜 시간으로 처리한다.
- 가능 시간은 "미팅에 **있을 수 있는** 시간"이다. 규칙 경계에는 이동시간을 붙이지 않는다.
- 범위는 오늘부터 60일, 시각은 Asia/Seoul 기준. 슬롯 시작 시각은 30분 간격.

### 4.2 장소와 미팅 양식
- 호스트가 장소를 등록한다. 데모 기본값은 **회사 근처 / 특정 장소 / 온라인**.
- 호스트가 미팅 양식을 여러 개 정한다(이름, 길이). 클라이언트는 따로 고르지 않고, 슬롯마다 (시간, 장소, 양식)이 함께 정해진다.

### 4.3 이동/준비 시간 (미팅 **앞뒤 모두** 적용)
"직전/직후 위치"는 미팅 앞뒤로 가장 가까운 **오프라인 일정**의 장소다. 온라인 일정은 시간만 차지하고, 이동의 출발점이나 도착점이 되지 않는다. (예: 12:50까지 회사 → 12:50–13:00 온라인 → 13:00 특정 장소 미팅은 "회사 → 특정 장소"로 판정해서 1시간이 필요하므로 불가.)

**호스트**

| 직전/직후 위치 ↔ 미팅 장소 | 회사 근처 | 특정 장소 | 온라인 |
|---|---|---|---|
| 회사 | 30분 | 1시간 | 0분 |
| 회사 외 장소 | 1시간 | 30분 | 0분 |
| 같은 장소 (미팅 연속 포함) | 0분 | 0분 | – |

- "회사에 있음"은 직전/직후 오프라인 일정의 장소가 회사인지로 판정한다. 근무시간 규칙은 이후 "장소=회사인 반복 일정" 생성 기능으로 추가하면 되고, 계산 로직은 바뀌지 않는다.
- 장소가 없는 일정은 "회사 외 장소"로 본다.

**클라이언트**
- 오프라인 미팅은 1시간, 온라인 미팅은 0분.
- 같은 장소 0분 규칙과 "직전/직후 오프라인 일정" 기준은 클라이언트에도 적용한다.

### 4.4 필터와 순위
- **반드시 조건**은 슬롯을 지운다. **선호 조건**은 점수를 더한다.
- 세기는 `반드시 / 강하게 선호 / 약하게 선호` 3단계다. AI는 단계만 고르고, 코드가 고정 가중치로 바꾼다.
- 항목: 날짜 범위, 요일, 시간대, 장소, 미팅 양식, 빠를수록/늦을수록, 앞뒤 여유.
- 같은 종류의 조건은 새 것으로 바꾸고, 다른 종류는 더한다.
- 현재 필터는 칩으로 보여주고 사용자가 지울 수 있다.

### 4.5 버튼 표시 조건 (하나라도 충족하면 상위 최대 3개 표시)
| 조건 | 판정 |
|---|---|
| 사용자의 명시적 요청 ("보여줘", "아무거나") | LLM이 `showOptions` 플래그로 알림 |
| 순위 3위 안쪽 확정 (3위 점수와 같은 점수가 4위 이하에 없음) | 코드 |
| 남은 슬롯 3개 이하 | 코드 |

- 버튼은 한 줄 형식이다: `10월 7일(화) 14:00 · 회사 근처 · 30분 커피챗`
- 남은 슬롯이 0개면, 어느 조건을 풀면 몇 개가 생기는지 알려준다.

### 4.6 예약
- 요청 = 슬롯 + 클라이언트가 직접 쓴 메시지. AI 선호 입력과는 **별도 필드**다.
- 상태: `pending → accepted | declined`. 요청 전송 시점에 코어가 가능 여부를 다시 검증한다.
- pending은 슬롯을 막지 않는다. 여러 클라이언트가 같은 시간에 요청할 수 있고, 호스트가 그중 하나를 고른다.
- 한 클라이언트의 pending 요청끼리는 호스트와 무관하게 시간이 겹칠 수 없다. 거절되면 그 시간은 다시 요청할 수 있다.
- 한 요청을 수락하면 시간이 겹치는 다른 pending 요청은 자동으로 거절된다. accepted가 되면 앱 안의 양쪽 캘린더에 일정으로 추가한다.

## 5. 범위

**MVP에 포함**
- 시드 캘린더 데이터, 시드 사용자 전환(로그인 없음)
- 가능 시간 규칙 편집, 호스트의 장소·양식 설정
- 슬롯 계산, 대화형 필터링, 버튼, 예약 요청
- 호스트 요청함(수락/거절)

**MVP에서 제외 (이후)**
- Google Calendar 연동 (`CalendarProvider` 인터페이스만 둔다)
- 실제 이동시간 API, 근무시간 규칙
- AI의 자동 예약 전송, 호스트용 AI(요청 요약·답장 초안)
- 외부 에이전트용 블록/API, 인증, 알림

## 6. AI 구성
- **Ollama Cloud** `/api/chat`. 어댑터는 kibitzer `apps/extension/src/providers/ollamaChat.ts`(origin/dev c1e3101)의 `postChat`을 이식한다. 대화용으로 `assistant` 역할을 추가한다.
- 모델: **`gemma4:31b`** (M4 평가로 확정, `implementation_plan.md` M4 결과 참조). 2026-09-29 무료 키로 호출해서 확인했고, deepseek-v4.1-flash, glm-5.3-flash, minimax-m3는 402(유료)였다.
- LLM 입력: 대화 내역, 현재 필터, 코드가 만든 결과 요약(개수, 분포, 동점 여부). 출력: 필터 변경분, 응답 문장, `showOptions`.

## 7. 데모 성공 기준
1. 시드 데이터에서 두 사용자의 60일 슬롯이 이동시간 규칙대로 계산된다(단위 테스트로 표 검증).
2. "다음 주 평일 오후, 온라인이면 좋겠고 금요일은 안 돼" → 필터 칩이 표시되고, 코드가 계산한 슬롯만 버튼으로 나온다.
3. 후보가 많으면 AI가 분포를 근거로 되묻고, "제일 빠른 걸로"라고 답하면 버튼이 나온다.
4. 버튼 → 메시지 → 전송 → 호스트 화면에 pending으로 표시 → 수락하면 양쪽 캘린더에 반영.
