# F01 — 로그인, 세션, 데모/실제 모드

## 왜 이렇게 만들었나
- 실제 사용에서는 개인 캘린더의 주인이 누구인지 분명해야 하고, 시연할 때는 설정 없이 바로 써 볼 수 있어야 합니다. [문서][코드]
- **로그인**과 **캘린더 읽기 권한**을 따로 받습니다. 로그인은 하되 캘린더는 연결하지 않는 선택이 가능하도록 하기 위해서입니다. [코드]
- 데모의 사용자 전환 기능이 실제 계정에 접근하는 통로가 되지 않도록, DB를 한 모드에만 묶습니다. [코드]

## 사용자는 이렇게 안내받는다
- 로그인 화면 문구: "Calendar를 연결하면 AI가 일정을 살펴보고, 미팅 가능한 시간과 선호를 함께 정해요. 연결은 선택이에요."
- 버튼: 실제 모드는 "Google 계정으로 시작", 데모는 "데모 시작"
- 상단 표시: 실제 모드는 이름과 로그아웃, 데모는 "현재 사용자" 선택 상자. 사용자를 바꾸면 예약하기 화면으로 이동합니다.

## 지켜지는 규칙
- 로그인이 끝나면 돌아갈 곳은 정해진 앱 내부 경로와 예약 링크로만 제한합니다. 외부로 튀거나 개인 리소스 ID가 새는 것을 막기 위해서입니다.
- 캘린더 권한은 **읽기 전용 세 가지**(캘린더 목록, 일정, 바쁜 시간)를 모두 받아야 연결됩니다. 로그인한 사람과 연결한 사람이 다르면 거부합니다.
- 세션은 7일입니다. 토큰은 해시로만 저장하고, 리프레시 토큰은 암호화합니다.
- 다른 사이트에서 보낸 변경 요청은 Origin 검사로 막습니다.

## 이식할 때
- 대상 MVP에 이미 로그인 기능이 있다면 그대로 쓰세요. **"캘린더 권한은 별도 동의"**와 **"연결은 로그인한 본인 것"**이라는 두 규칙만 가져가면 됩니다.
- 데모 모드는 선택 사항입니다. 다만 양쪽 역할을 한 화면에서 시연할 때는 매우 유용합니다. 사용자 전환, 예시 Calendar, 시드 계정, 미리 확정된 프로필, 미리 맺은 연락처로 구성됩니다.
