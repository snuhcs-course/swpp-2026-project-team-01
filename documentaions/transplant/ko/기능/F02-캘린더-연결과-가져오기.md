# F02 — 캘린더 연결, 선택, 가져오기, 새로 가져오기

## 왜 이렇게 만들었나
- 사용자가 직접 입력한 빈 시간이 아니라 실제 일정, 그중에서도 **시간과 장소**를 써야 가능한 시간이 정확해집니다. [문서]
- 읽기 전용입니다. Google 계정 하나에서 캘린더 여러 개를 고를 수 있고, Google에는 절대 쓰지 않습니다. [문서][코드]
- 가져오기는 "전부 되거나 전혀 안 되거나"입니다. 일부만 실패한 것을 "일정 없음"으로 보이거나 기존 데이터를 지우지 않습니다. [코드]
- 원본이 알려 주는 상태(거절함, 한가함, 취소됨, 근무 위치 표시)를 추측으로 덮지 않습니다. [코드]

## 사용자는 이렇게 안내받는다
- 화면 설명: "선택한 캘린더를 읽어 기존 일정과 겹치지 않게 준비해요. 과거 8주 관찰과 앞으로 60일의 일정을 사용해요."
- 오른쪽 위 상태 표시: 직접 설정 사용 / 일정 반영 중 / 일정을 가져와 주세요 / 권한 재연결 필요 / Calendar 없이 계속할지 선택해 주세요
- **1. 계정 연결** 카드
  - 연결되면 버튼이 "✓ Google Calendar 연결됨"으로 잠깁니다.
  - "Calendar 없이 직접 설정하기" 링크가 늘 옆에 있습니다.
  - 데모는 "예시 Calendar 연결" 버튼이 대신 나옵니다.
- **2. 사용할 캘린더** 카드
  - 캘린더마다 체크박스가 있고, "일정 정보 / 바쁜 시간만"과 시간대가 표시됩니다.
  - 버튼 세 개: **저장하기**, **AI로 설정 시작하기**, **연결 해제 · 가져온 정보 삭제**
  - 버튼 아래에 두 버튼의 차이를 설명하고 "미팅 가능 시간은 직접 확인해야 확정돼요"라고 덧붙입니다.
- 연결하고 돌아오면 목록을 따로 누르지 않아도 자동으로 불러옵니다.
- 내 캘린더 화면에서도 "일정 새로 가져오기"를 할 수 있습니다. 실패하면 "기존 일정은 그대로 유지했어요"라고 안내합니다.

## 지켜지는 규칙
- **가져오는 기간**
  - 처음 가져오기: 지난 8주 + 앞으로 60일
  - 이후 새로 가져오기: 앞으로 60일만
  - 지난 8주 데이터는 분석용으로 따로 보관합니다.
- **바쁨으로 보는 것과 아닌 것**
  - 취소, 내가 거절한 초대, "한가함" 표시, 근무 위치 표시는 바쁨이 아닙니다.
  - 미응답·미정 초대는 바쁨으로 봅니다.
  - 길이가 0인 일정(마감 표시 등)은 빼고 가져옵니다. 이것 때문에 실제 계정 두 개가 아예 가져오지 못한 적이 있어서 고쳤습니다. [커밋]
- **같은 일정의 판단**
  - 여러 캘린더에 같은 일정이 있으면, Google이 같은 일정이라고 알려 줄 때만(iCalUID) 하나로 합칩니다.
  - 제목과 시간이 같다는 이유만으로 합치지 않습니다.
- **장소 해석**
  - 장소와 화상회의 링크가 함께 있으면 "알 수 없음"으로 두고 사용자 확인을 기다립니다. 참석 방식을 자동으로 정하지 않습니다.
  - 종일 일정은 그날을 막지만 이동 계산의 출발점은 되지 않습니다.
- **연결 해제**
  - 가져온 일정, 분석, 분류, 보정 내용을 모두 지웁니다.
  - 앱에서 만든 일정, 프로필, 요청은 그대로 둡니다.
- 동시에 두 번 가져오지 않도록 막습니다. 페이지 수, 일정 수, 시간에도 상한이 있습니다.

## 이식할 때
- 가장 값어치 있는 부분은 **일정 정규화 규칙**(`core/calendar.ts`)입니다. 입출력이 없는 순수 함수라서, 어떤 캘린더 공급자를 쓰든 이 형식으로 넣으면 됩니다.
- 스냅샷과 동시 실행 방지까지 그대로 가져올지는 대상 MVP의 규모에 따라 정하면 됩니다. 단순하게는 "한 트랜잭션에서 통째로 교체"로도 충분합니다.
- **저장하기 / AI로 설정 시작하기** 두 버튼은 F03–F05로 넘어가는 입구입니다. 그 기능들을 함께 가져간다면 유지하세요.
