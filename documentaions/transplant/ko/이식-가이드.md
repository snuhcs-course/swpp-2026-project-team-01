# 이식 가이드

목표는 이 MVP의 기능, 의도, 디자인을 다른 팀원의 MVP에 골라서 옮기는 것입니다. 대상 MVP가 아직 정해지지 않았으므로, 시작 전에 맨 아래 체크리스트로 대상을 먼저 확인하세요.

## 1. 기능 사이의 의존 관계
- **F01 로그인** → F02 캘린더 → (F03 확인·보정, F04 분석) → F05 시간 프로필
- **F06 호스트 설정 + F02 캘린더 + F05 프로필** → F08 가능 시간 계산
- **F07 예약 링크 + F08 + F05** → F09 예약 탐색 → F10 요청
- **F02 + F10** → F11 내 캘린더
- **디자인 시스템과 공통 장치**는 모든 기능이 함께 씁니다.

## 2. 추천하는 옮기는 순서
1. **디자인 시스템**: 의존이 없고, 이후 화면을 그대로 붙이기 쉬워집니다.
2. **가능 시간 계산 엔진**(F08)과 겹침 규칙: 순수 코드이고 테스트도 함께 옵니다.
3. **시간 프로필**(F05): 직접 편집만 먼저 옮깁니다.
4. **호스트 설정**(F06): 여기까지 오면 앱 안 일정만으로도 예약이 됩니다.
5. **예약 탐색 엔진**(F09): AI 없이 칩·명령부터 옮깁니다.
6. **요청·수락**(F10)
7. **캘린더 가져오기**(F02) + 결정 직전 재확인
8. **AI 연결**: 조건 해석, 프로필 추출
9. **분석·브리핑**(F04) + **확인·보정**(F03)
10. **예약 링크**(F07), **내 캘린더**(F11): 필요한 입력이 갖춰진 뒤라면 아무 때나 옮겨도 됩니다.

## 3. 목적별 최소 묶음
| 원하는 것 | 가져갈 것 | 빼도 되는 것 |
|---|---|---|
| "AI가 제안하고 내가 확정하는" 온보딩만 | F02 정규화, F04, F05, AI 연결 3종 | 대상에 이미 예약이 있다면 F09·F10 |
| 기존 예약 흐름의 가능 시간을 더 정확하게 | F08 + F02 정규화 + F05 허용 시간 | AI 전부 |
| 대상의 슬롯 위에 대화형 예약만 | F09 엔진 + 조건 해석 | 이동시간 규칙 |
| 시각적 정체성만 | 디자인 시스템 | 나머지 전부 |

## 4. 코드에는 있지만 지금 여정에서는 안 쓰는 것 (옮기기 전에 결정 필요)
- **AI가 직접 쓰는 예약 답장과 관련 기능**: 되묻기, 길이 먼저 묻기, 같은 후보 반복 방지, "어떤 조건을 풀면 몇 개" 안내. 경로가 막혀 있고, 테스트만 남아 있습니다.
- **예전 요청 생성·수락 함수**: 새 방식으로 대체됐고, 부르는 곳이 없습니다.
- **검색 가능한 "가져온 일정" 목록 컴포넌트**: 어느 화면에도 붙어 있지 않습니다.
- **예전 요일별 가능 시간 API**(`/api/availability`): 화면에서 쓰지 않습니다(빠져 있던 `await`는 `places`·`meeting-types`·`events`와 함께 고쳤습니다).

## 5. 설계 문서와 실제 코드가 다른 점 (코드가 기준)
| 주제 | 설계 문서 | 실제 코드 |
|---|---|---|
| 예약 대화 한 턴 | LLM 2회, AI가 1–3문장으로 답하고 후보가 많으면 되묻기, 버튼은 조건을 만족할 때만 | LLM 1회(해석), 답은 코드 문장, **매번 후보 최대 3개** |
| 미팅 길이 먼저 묻기 | 양식이 여러 개면 길이부터 질문 | 현재 흐름에 없음 |
| 직전과 같은 후보 | 반복하지 않고 안내 | 현재 흐름에 없음 |
| 온보딩 대화 | 근거를 붙여 제안하는 AI 대화 | AI는 값만 추출하고, 답은 주제별 정해진 질문 + 코드 브리핑 |
| 최종 확인 | 별도 페이지 `/onboarding/review` | 같은 화면 안에서 상태만 바뀜 |
| 헤더 "설정 이어가기" | 있음 | 없음. 첫 화면 이동과 빈 상태 안내로 대신 |
| 최신 기본 선호 적용 | 프로필이 바뀌었을 때 제공 | 접힌 메뉴 안에 늘 있는 링크. 바뀐 것을 감지하지는 않음 |
| 예약 링크 | MVP 범위 밖 | 구현됨. 연락처에게만 예약 가능 |
| 확인 창, 분석 질문 답변, 근무시간 추정, 예시 Calendar, 충돌 배지 | 없거나 일부만 | 구현됨 |

## 6. 대상 MVP를 열기 전 체크리스트
- **기술 스택**: Next.js App Router, Postgres, Tailwind v4, Zod v4인가? Supabase Auth를 쓴다면 로그인은 대상 것을 쓰고, "캘린더는 별도 동의"만 유지합니다.
- **시간대**: 이 코드는 **한국 시간 전용**입니다. 여러 시간대가 필요하면 시간 함수부터 일반화해야 합니다.
- **ID 규칙**: 후보는 장소·양식 ID를 쓰지만, 프로필 선호에는 ID를 넣지 않습니다.
- **용량 상한**: 분석은 한 번에 120건, 캘린더는 100페이지·5만 건까지입니다.
- **필요한 테이블**: 영문판 각 기능 문서의 "Data / API"에 정리했고, DDL은 `supabase/schemas/scheduler.sql`에 있습니다.
- **비밀값**: Ollama 키, Google OAuth, 토큰 암호화 키, 수락 확인 서명 키

## 7. 옮긴 뒤 반드시 다시 확인할 것
1. 이동시간 표의 모든 칸
2. 필수 조건은 자동으로 풀리지 않고, 선호가 안 맞아도 0개가 되지 않음
3. 호스트 선호는 클라이언트 동점일 때만 순서를 바꿈
4. 초안은 계산에 쓰이지 않고 확정 버전만 쓰임. 허용 시간이 비면 예약 불가
5. 수락 직전 자동 거절 목록이 바뀌면 막힘
6. 캘린더 새로 가져오기가 실패해도 이전 데이터가 유지됨
7. 원본이 바뀐 일정의 보정은 "다시 확인 필요"로 표시됨
8. AI가 만든 숫자가 검증 없이 사용자에게 보이지 않음
