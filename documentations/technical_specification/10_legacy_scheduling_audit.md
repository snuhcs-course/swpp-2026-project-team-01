# Legacy scheduling assertion audit

Date: 2026-10-09
Source: `5c305d9^:supabase/functions/_shared/modules/scheduling/index_test.ts` (21 named tests).

This audit compares observable behavior, not old module names or types. The [implementation plan](04_implementation_plan.md) requires preservation or explicit reconciliation of relevant assertions. Existing [PRD travel scope](../02_product_requirements.md#travel-time-checks), [interval design](01_backend_architecture.md#deterministic-interval-core), and [manual-allowance design](01_backend_architecture.md#host-confirmed-manual-travel-allowances) govern the replacement. An identified difference is not automatically proof of equivalence or permission to change product behavior.

## Evidence locations

- [Interval tests](../../lib/server/scheduling/intervals.test.ts): full-duration filtering, host-local dates, both calendars, focus/buffers, sampling, input bounds, DST and overnight ownership.
- [Travel tests](../../lib/server/scheduling/travel.test.ts): both gaps, exact departure/modes, provider uncertainty, fresh context and explicit manual allowances.
- [Adjacent-event tests](../../lib/server/calendar/adjacent.test.ts): virtual commitments, unknown locations, bounded reads, ambiguity, private-field minimization and changed context.
- [Authorized evaluator integration](../../tests/integration/availability-evaluation.test.ts): actual Auth/PostgREST/PostgreSQL, authority and revisions, private evidence, manual decisions, publication, host/requester projections and current-context races. Calendar/Routes transports are controlled fixtures.
- [Allowance persistence](../../supabase/schemas/29_travel_allowances.sql): host/session attribution, immutable values, revocation, exact retry identity and current context.

## Assertion-by-assertion comparison

| Legacy assertion (source line) | Current evidence and disposition |
|---|---|
| Explicit public windows on fifteen-minute boundaries (67) | **Changed contract.** `presentation sampling starts at the feasible window...` verifies 10:01 and 10:16 samples for a 10:01 window with 15-minute spacing, an unsampled valid exact start, and explicit truncation. The documented continuous-window design replaced UTC quarter-hour rounding; no claim of identical generated slots. Publication remains evidence-backed and allowlisted. |
| Entire duration, focus, buffers and requester busy before routes (81) | **Preserved and strengthened.** The actual evaluator integration now checks six hard-conflict cases, each persisting conflict evidence with `travel:null` and zero new adjacent-event/Routes calls. Cases include overlap near the end, a later commitment's buffer, focus, wrong elapsed duration, working hours ending mid-meeting, and requester Calendar conflict. |
| Host timezone and whole interval including buffers (112) | **Part preserved, buffer policy changed.** Host-local weekday and full-interval exclusion remain tested. `host working-hour endpoints...` verifies a 19:00 Seoul start is allowed at the hours boundary with ten general-buffer minutes when no commitment is nearby. General buffers expand busy/focus commitments; they do not shrink the working-hours window. This is the documented replacement policy. |
| Required duration and no-match never relaxes rules (130) | **Part preserved, duration policy changed.** Empty feasibility stays empty and invalid durations reject. The actual integration now has a 45-minute host default and a 30-minute request: the complete 30-minute candidate passes, while a 15-minute candidate fails before travel. Requested duration governs; equality with the host default is no longer required. |
| Both adjacent route estimates, buffers, departure and mode (143) | **Preserved with explicit departure-policy change.** Both independently insufficient legs and a one-nanosecond deficit fail. Current queries depart after the general transition buffer, then reserve the separate extra travel buffer after journey time. The old fixture queried at the event/meeting end. Current tests assert both exact endpoints/departures and independent per-trip modes. |
| Unknown virtual whereabouts never implies home/video location (188) | **Preserved through different input ownership.** Adjacent-event tests strip virtual conference location even when Calendar supplies text. Unknown endpoints require clarification. A standalone caller's `physicalLocation` is no longer trusted evidence; an authenticated current-context manual decision supplies the place and time. |
| Confirmed whereabouts after a virtual event resolve travel (201) | **Replaced interaction.** The old free-standing `physicalContext` array is absent. Host-confirmed manual boundaries supply the endpoint, time, mode and duration for the specific leg. Known future boundaries cannot move; the past-origin integration and travel test require an explicit current place/time at or after now and the old boundary. This is not wire compatibility with legacy context objects. |
| No initial whereabouts remains unresolved despite home setting (216) | **Preserved, resolution interaction replaced.** Empty adjacent reads produce unknown neighbors, not home or zero travel. Both unknown legs require independently confirmed endpoint/time/duration decisions. Pure travel and actual private-review integration cover the replacement. |
| Online candidate cannot hide adjacent physical trip (227) | **Unresolved legacy difference.** Current `evaluateTravel` marks online legs not required, and the authorized integration verifies online evaluation skips private event-location reads. PRD FR-12 and the archived feasibility design describe checks on both sides of physical meetings; online-only setup deliberately omits venue/transport questions. The old online `candidatePhysicalLocation` behavior has no replacement. Do not count this assertion as preserved or silently add whereabouts/travel requirements to online-only setup. A product/spec decision is required to restore it or explicitly retire the old obligation. |
| Missing endpoints/routes, invalid estimates and provider errors (235) | **Preserved.** Typed no-route/unsupported/failure results, thrown provider errors and malformed/negative/stale estimates remain clarification. Provider exception text is absent from returned evidence. The actual integration verifies failed event reads and route uncertainty without publication of feasible candidates. |
| Public candidates omit adjacent addresses/diagnostics (256) | **Preserved at current projection boundaries.** The actual evaluator check returns only its four-field receipt; private evidence stays service-only. Publication/private-review/browser coverage verifies no private rules, locations, reasons, allowance IDs or fingerprints in requester output. Internal `read()` remains a server-only result, not a public DTO. |
| DST gaps/repeated clocks require resolution (264) | **Preserved, API changed.** Shared local-time conversion rejects ambiguous/nonexistent clocks. Already offset-qualified instants are accepted through the strict interval contract; both fold offsets are exercised by elapsed-duration sampling. The former numeric-offset resolver argument is not part of the new API. |
| Real-time interval across DST transitions (294) | **Preserved.** Actual elapsed-duration and full-window checks reject intervals that cross the local closing time. Tests cover shorter/longer New York nights, both fold offsets, and Lord Howe's half-hour transition. |
| Invalid timestamps, timezone, limits and oversized windows (309) | **Preserved.** Strict instant/IANA/window contracts reject malformed, offset-free and oversized values. Invalid sampling bounds throw before generating candidates. Existing setup/request contract tests cover impossible dates. |
| Overlap merge, limit and half-open busy endpoints (340) | **Preserved.** Overlapping/touching ranges coalesce without duplicates or fabricated gaps. Sample limits return explicit truncation. Half-open endpoints and sub-millisecond overlap are verified independently. |
| Overnight belongs to preceding local weekday (359) | **Restored and deployed.** See [overnight rollout](05_rebuild_evidence.md#deployed-overnight-host-hours--2026-10-09): previous-day expansion, exact shared/SQL contracts, DST, midnight/week boundaries, browser review and production rollback acceptance. |
| Specific manual allowances resolve both missing routes with buffers (385) | **Preserved.** `Both unavailable trips require their own manual allowance...` verifies one leg cannot resolve the other, both allowances avoid provider calls, both buffers count once and a longer allowance still conflicts. Actual integration verifies authenticated creation, current evidence, concurrent retry identity and subsequent evaluation. |
| Manual allowance resolves unknown virtual location without invented endpoint (409) | **Changed contract.** Unknown-place duration alone was accepted by legacy code. Current confirmation requires a host-supplied place and boundary time, never inferred from a video link/home setting. Strict input tests reject null endpoints; known-location mismatch rejects. The stronger explicit-context requirement is documented in the existing manual-allowance design. |
| Changed rules/version/slot/locations/mode/neighbors invalidate allowances (421) | **Preserved through current fingerprints and authority.** New travel tests invalidate both stored legs for nine whole-context mutations. Actual integration adds request/rule revisions, changed provider versions, connection/account changes, revocation and races. Confirmed decisions never excuse a later hard conflict. |
| Wrong host/leg/confirmation/zero/duplicate allowance cannot authorize travel (469) | **Preserved authority, changed duplicate representation.** Host/session ownership and current evidence come from verified Auth and SQL, not caller-supplied host/confirmation fields. Zero/negative duration and malformed boundary fail strict parsing. Direction is bound into the leg fingerprint. Concurrent exact retries produce one immutable row; a new same-context leg decision revokes the prior row under a request lock. Arbitrary duplicated arrays are no longer a public input. |
| Manual allowance cannot waive busy/focus or reveal private details (498) | **Preserved.** Hard interval rejection precedes travel consumption, as the new actual evaluator cases verify. Existing integration rejects confirming an allowance against hard-conflict evidence; private decision/reason/endpoint data stays out of guest projections and published candidates. |

## Remaining work

Twenty assertions now have an explicit preserved/replacement mapping; the online-adjacent-trip assertion remains unresolved, rather than passed by a test of the narrower implementation. This does not complete the wider 34-file legacy inventory, prove live Calendar/Routes compatibility, or close the full scheduling acceptance matrix. No runtime behavior was changed by this audit. Any future decision on online travel must reconcile the owning PRD, capability spec, onboarding policy, private review and booking revalidation before implementation.

## Request-evaluation assertions

Additional source: `5c305d9^:supabase/functions/_shared/modules/requests/evaluation_test.ts` (eight named tests). This maps the actual evaluator boundary separately from the pure scheduling core.

| Legacy assertion (source line) | Current evidence and disposition |
|---|---|
| Fresh requester busy and deterministic candidates saved under CAS (43) | **Preserved through split evaluation/publication.** The authorized integration checks both Calendar ranges, exact remaining windows, revision/rule changes during provider work, and current evidence before publication. Private exact assessments precede allowlisted publication; the old one-step candidate save is deliberately forbidden. |
| Requester Calendar failure blocks evaluation (74) | **Preserved.** The integration requires `PROVIDER_UNAVAILABLE`, a durable requester failure flag, empty candidates and cleared proposal/evaluation state. Only explicit manual replacement removes requester Calendar dependence; it cannot clear a host failure. |
| Initial stale revision rejected before Calendar access (95) | **Preserved and strengthened.** New actual Auth/RPC assertions reject the previous revision with zero refresh, free/busy, adjacent-event or Routes calls. The request revision, check ID and check start time remain byte-for-byte unchanged. Existing races separately verify changes after work starts. |
| Ranking reserves request budget and preserves revision/rules CAS (110) | **Preserved authority, changed model input.** Ranking tests verify reservation before the real model adapter, expiry after reservation and exact candidate-ID permutations. The authorized integration exercises concurrent budget claims and stale publication. Raw private preference text is no longer passed to ranking; explicit deterministic preference decisions precede it. |
| Expired route budget remains unresolved with a resolution action (149) | **Changed failure contract.** The shared deadline tests fence acquisition and persistence, abort provider work and prevent late responses from saving evidence or publishing. Expiry returns `PROVIDER_UNAVAILABLE` instead of saving the legacy unresolved blob/action. Routes uncertainty within a live deadline still produces private clarification. See the archived evaluation-deadline contract; an expired evaluation never certifies availability. |
| Trusted online receipt removes physical inference without Routes (179) | **Safety preserved; online travel scope remains unresolved above.** The new adjacent-context test verifies an HTTPS receipt location cannot become a physical endpoint. Current online locations require HTTPS; legacy free-text `Host link` is not a valid replacement input. |
| Confirmed receipt blocks availability during Calendar lag (217) | **Preserved with real persistence.** The integration switches requester availability explicitly to manual and makes host Calendar empty. The confirmed 11:25–12:00 booking still closes availability at 11:15, including its ten-minute buffer. Thus neither requester busy data nor a matching provider event can accidentally supply the tested protection. |
| Moved provider event preserves frozen interval and explicit mode (237) | **Frozen protection and input immutability preserved; mode overwrite replaced.** The integration preserves both returned 10:00–10:30 busy time and the frozen 11:25–12:00 booking, rejects an exact overlapping candidate before travel, and leaves provider input unchanged. The new adjacent-context test gives local/provider commitments the same Calendar/event identity: both versions affect evidence, the frozen HTTPS receipt has no physical endpoint, and a later provider location is retained. Current code intentionally does not overwrite a provider edit with the receipt's mode. |

All eight assertions have a traced disposition, including the explicit differences above. This audit does not resolve online travel scope, prove live provider behavior, or complete the wider legacy inventory.
