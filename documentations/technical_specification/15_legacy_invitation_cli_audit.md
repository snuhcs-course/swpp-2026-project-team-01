# Retired invitation CLI assertion audit

This maps all nine tests in `5c305d9^:scripts/manage-invitations.test.mjs` to the replacement operator, CLI and durable delivery worker. It contributes to the [Phase 2 audit](04_implementation_plan.md#phase-2--build-contracts-identity-schema-and-durable-effects); it does not close live invitation inbox acceptance or the rest of the retired test inventory.

The [operator design](../../openspec/changes/deliver-operator-invitations/design.md) intentionally replaces synchronous CLI sending and local dispatch receipts with transactional database delivery records. Manual codes are written only to exclusive private artifacts. Email delivery is a separate leased worker, with durable dispatch before network I/O. The CLI never reports a queued invitation as delivered.

| Retired assertion | Current evidence and disposition |
|---|---|
| Remote issue persists a private receipt before exactly one Cloudflare send | The [delivery integration](../../tests/integration/invitation-delivery.test.ts) inspects SQL during the actual adapter call and requires `dispatched` before HTTP; duplicate jobs cannot send twice. Message content directs Google login at `/app` without code-bearing URLs. Local receipt state is replaced by a private SQL record; codes are derived in memory rather than stored in it. The [CLI integration](../../tests/integration/invitation-cli.test.ts) and [artifact tests](../../lib/operator/private-artifact.test.ts) verify 0600 manual files under 0700 directories. |
| Manual remote/local issue and revoke never call Cloudflare | Issue only invokes the service RPC. Local CLI integration runs with empty Cloudflare configuration and requires zero delivery jobs after issuance, status, recovery and revocation. Manual remote behavior is specified by the current delivery mode; SQL tests and [operator integration](../../tests/integration/operator-invitations.test.ts) check mode, authority and send-free revocation. Remote default remains queued Cloudflare delivery, not an inline send. |
| Missing Cloudflare configuration fails before invitation RPC | New [operator tests](../../lib/server/identity/invitation-operator.test.ts) assert zero RPCs for missing/malformed account, missing/newline-bearing token, wrong sender, preview environment, missing derivation key and public database key. |
| Rejected issuance does not send email | New operator tests propagate the exact RPC conflict without additional calls. The CLI has no direct send path; actual integration verifies conflicting retries do not create another invitation. Atomic SQL issuance owns any delivery job. |
| Lost/suppressed send outcomes retain issued code without retrying | Delivery integration covers lost response, rejection, bounce, suppression and unverified acceptance, then invokes the worker again and requires no additional send. Suppression is now a distinct terminal state. Codes are recovered from the original derivation context; CLI retry preserves invitation, expiry and code. |
| Receipt failure retains recovery code and prevents send | The former synchronous receipt contract is retired. Manual CLI reserves output before issuance, rejects unsafe paths without new invitations, and simulates permission failure after committed issuance. Explicit recovery writes the same issued code to a fresh private file; ordinary output contains only diagnostic identifiers. Remote email safety uses SQL dispatch fencing and lost-commit tests, independently of manual files. |
| Existing receipt is never reused for another send | Artifact tests refuse overwrite and preserve existing bytes. Actual CLI duplication fails before another issuance and a fresh-file exact retry recovers the original invitation/code. Durable worker duplicate-job checks preserve the separate no-resend obligation. |
| Codes encode 80 bits in sixteen readable characters | Current [code tests](../../lib/server/identity/invitations.test.ts) verify an independent HMAC/Base32 vector and browser redemption. Ten HMAC bytes are encoded as sixteen RFC 4648 Base32 characters, isolated by project, operator, recipient, retry key and delivery mode. This intentionally replaces random Crockford-like encoding; old all-zero/all-255 alphabet vectors are not the current contract. |
| Invalid generated code fails before issuance | Codes are internally derived; there is no caller `makeCode` hook. Code tests reject injected code, expiry, invalid recipient/operator/retry key and malformed dedicated keys. New operator tests inspect the complete SQL request and require only normalized context and the code hash, with no plaintext code or provider/server secret. |

Fresh verification is recorded in the [evidence ledger](05_rebuild_evidence.md#legacy-invitation-cli-acceptance--2026-10-10). Synthetic provider acceptance does not prove receipt by a real mailbox. No provider message is sent by this audit, and no production application or schema behavior changes.
