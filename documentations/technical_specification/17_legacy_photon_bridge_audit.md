# Retired Photon bridge assertion audit

This maps all 23 tests in the five files under `5c305d9^:apps/photon-bridge/test/`. The replacement uses signed Spectrum webhooks, a durable database inbox/outbox and eve execution, with SDK 2.2.0 gRPC calls for outbound delivery. It has no standalone subscription bridge. This audit contributes to [Phase 7](04_implementation_plan.md#phase-7--add-verified-host-imessage-continuity); it does not establish live provider or iPhone compatibility.

## Assertion map

The first thirteen rows correspond to `bridge.test.mjs`, in source order.

| # | Retired assertion | Replacement and disposition |
|---|---|---|
| 1 | Normalize the private low-level iMessage event | **Envelope changed.** [Webhook tests](../../lib/server/photon/webhook.test.ts) verify original UTF-8 signatures and minimized sender, route, line, message, body and timestamp. Spectrum does not use the former stream sequence or `message.received` envelope. |
| 2 | Reject groups, forged sender/service, forwarded content and mismatched chat | Group, platform and conflicting route rejection is covered by webhook tests; SQL binds channel authority to the exact sender/line/space. [Linking integration](../../tests/integration/photon-linking.test.ts) rejects another browser or host using the challenge. **Legacy difference remains:** the old adapter rejected every `isForward` message. The new Spectrum envelope does not inspect that low-level flag, so blanket forwarded-content rejection is not claimed. Forwarded challenges must still fail to confer linking or setup authority under the [agreed requirement](../../openspec/changes/conversational-host-setup/specs/conversational-host-setup/spec.md); actual provider forwarding representation needs live verification. |
| 3 | Serialize events and deduplicate IDs across restart | [Signed execution integration](../../tests/integration/photon-execution.test.ts) verifies original input recovery, one model effect, immutable reply and restart continuity. [Ingress integration](../../tests/integration/photon-ingress.test.ts) races eight duplicate receipts and verifies one inbox/job pair. Stream sequence checkpointing is replaced by persisted receipt ordering. |
| 4 | Checkpoint a dropped group without forwarding its body | Webhook validation drops groups before any RPC. No stream checkpoint exists; unsupported events receive an empty acknowledgment. The group body does not enter the application inbox. |
| 5 | Recheck after claim and suppress after unlink | [Reply worker tests](../../lib/server/photon/replies.test.ts) require final authorization after provider preflight. Signed execution integration revokes the link before that callback and verifies no send. |
| 6 | Lost send response stays uncertain; known identity reconciles without resending | [Transport tests](../../lib/server/photon/transport.test.ts) and [installed-SDK gRPC tests](../../tests/providers/photon-grpc.test.ts) disable retries, preserve uncertainty and read only the persisted reference. Send acceptance and device delivery remain distinct. |
| 7 | Empty/ambiguous targeted history stays uncertain | **History search retired.** Missing references trigger no provider read, and reads that fail or return an unrelated message stay uncertain. There is no body/time-window search from which to infer success. |
| 8 | Transient chat lookup failure cannot advance a checkpoint | **Lookup/checkpoint protocol retired.** The signed webhook contains route evidence; ingress acknowledges only after the database commit. Ingress integration verifies lost acknowledgment and receiver revocation; webhook tests return failure for unavailable persistence. |
| 9 | Same-text history cannot manufacture provider identity | No history matching exists. Null-reference reconciliation stays uncertain without contacting Photon. Text equality is necessary to bind a send response but is never sufficient to recover an unbound message. |
| 10 | Stop closes a provider that finishes initialization late | **Standalone lifecycle retired.** Each outbound operation creates one client and closes it in `finally`; transport tests cover success, uncertain response, authorization rejection and errors. This is not evidence for a persistent stream's shutdown semantics. |
| 11 | Dispatch the persisted client ID once and validate the response | Installed-SDK gRPC tests verify the exact serialized ID/body/chat and disabled retry/idempotency generation. The [response-binding fix](05_rebuild_evidence.md#photon-response-identity-validation--2026-10-10) rejects a different body, sender or chat before saving identity. |
| 12 | Preserve validated identity after backend acknowledgment failure | The [receipt persistence fix](05_rebuild_evidence.md#photon-delivery-receipt-persistence--2026-10-10) adds one identical receipt-write retry for transient errors with known identity. Reply and handoff integrations fail before commit, lose the committed retry acknowledgment, and reconcile the saved identity without resending. Persistent failure or a crash before persistence remains uncertain. |
| 13 | Never persist mismatched send identity | Transport tests require exact frozen text and outgoing chat evidence. Reconciliation also requires the exact requested GUID and retains the old reference for inconclusive evidence. SDK tests exercise mismatched body and GUID on the wire. |

## Remaining acceptance

The audit found and repaired response-identity binding, transient receipt persistence and the missing handoff preview guard. It records architectural differences explicitly rather than claiming the old stream tests run unchanged. The installed SDK tests use a local gRPC server; database/runtime integrations use synthetic identities and deterministic outbound transports. Live receiver configuration, one active consumer, provider retry behavior, forwarded-message representation and actual iPhone rendering/replies remain unverified. Keep those gates open in the implementation plan.
