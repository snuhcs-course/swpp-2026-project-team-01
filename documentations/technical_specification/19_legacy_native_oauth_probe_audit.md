# Retired native OAuth probe assertion audit

This maps all seven tests in `5c305d9^:scripts/p0/oauth-probe-native.test.mjs`. The former probe tested an isolated Supabase OAuth server and a diagnostic MCP tool through a separately registered Codex client. The rebuilt application now owns its OAuth issuer, resource-bound application grants and public MCP endpoint. The product's `fmat` CLI is a separate client; its tests do not establish native Codex or other named-client compatibility.

| Retired assertion | Replacement or disposition |
|---|---|
| New native run preserves active/pending client lifecycles | The temporary native-run registry and replacement command are retired. Application [registry tests](../../tests/integration/agent-oauth-registry.test.ts) verify client registration/authorization ceilings, expiry and disablement after lock waits, while [grant tests](../../tests/integration/agent-oauth-grants.test.ts) cover current authority and revocation. A future native-client probe must still avoid overwriting active client registrations or replacing a running login. No native client was reconfigured by this audit. |
| Refresh proof requires same audited session after natural expiry | **Issuer changed.** [Service integration](../../tests/integration/agent-oauth-service.test.ts) verifies persisted hashed refresh tokens, scope narrowing, rotation, replay-triggered revocation and explicit revoke through real PostgREST. Supabase session/audit-table fields from the retired probe no longer describe the application's OAuth grant. Native-client automatic refresh after natural expiry remains unverified and must bind the same issuer/resource/client/actor/grant. A direct fixture refresh is not that proof. |
| Pending authorization binds isolated endpoint/resource/redirect/scopes | The isolated GoTrue endpoint and identity-only scope set are retired. [Current CLI OAuth tests](../../lib/cli/oauth.test.ts) bind discovered same-origin issuer/endpoints, exact `/mcp` resource, PKCE/state, registered loopback redirect and application role scopes. Foreign metadata, private keys, wrong claims and actor promotion fail closed. [Loopback listener tests](../../lib/cli/login.test.ts) reject foreign host/origin/path/method, duplicate parameters and repeated callback exchange. These exercise `fmat`, not a native agent's pending login. |
| Codex login uses installed CLI's exact DCR/scopes arguments | Historical command generator retired. Its old flags, version and isolated identity scopes are not copied into current setup instructions. Actual Codex integration still requires checking the installed client's supported discovery/DCR flow and recording its version against the release endpoint. No current CLI compatibility is inferred from this historical assertion. |
| Only an actual diagnostic MCP event with exact bindings counts | Historical JSONL parser and `diagnostic.read` endpoint retired. The acceptance rule remains: a model's final prose cannot prove a tool call. Current server/CLI fixtures verify protocol contracts, but each named-client journey still needs actual client tool events and the matching application grant/outcome; token values and private payloads must stay out of tracked evidence. |
| Structured initialization failure cannot invent a tool call | Historical failure parser retired. Native initialization/discovery failure remains a failed or unsupported journey, never a successful application call. The [compatibility tasks](../../openspec/changes/validate-provider-and-agent-compatibility/tasks.md) keep untested clients open. No synthetic success is recorded for absent events. |
| Client approval denial differs from server authorization denial | Historical parser retired. A client-side tool approval refusal cannot prove server rejection or product authorization. Actual acceptance must distinguish initialization failure, local tool refusal, OAuth denial/revocation and an authorized application result. Generic client tool approval is also not proposal-specific human approval. |

The old fixture names, diagnostic endpoint and evidence schema are deliberately not preserved as product interfaces. The strict provenance and lifecycle obligations remain prerequisites for future live client tests. [Fresh audit evidence](05_rebuild_evidence.md#legacy-native-oauth-probe-audit--2026-10-10) records server-side verification only. Complete requester and host journeys remain open separately for Dots, Muse, Instinct, ChatGPT, Codex, Claude and Claude Code.
