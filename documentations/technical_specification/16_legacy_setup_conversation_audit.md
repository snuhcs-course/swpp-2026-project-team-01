# Retired setup conversation assertion audit

This reviews all nine tests in `5c305d9^:supabase/functions/_shared/modules/onboarding/conversation_test.ts`. It contributes to the [Phase 2 command migration](04_implementation_plan.md#phase-2--build-contracts-identity-schema-and-durable-effects). The replacement uses eve input/step persistence, current execution grants and typed draft tools rather than the old synchronous extraction-and-append handler.

## Assertion map

| Retired assertion | Replacement evidence and disposition |
|---|---|
| Model failure saves a safe turn without confirming settings | [Actual-runtime failure tests](../../tests/runtime/setup-provider-failure.test.ts) admit input through the real conversation channel and exercise outage, timeout, missing key, authentication error, rate limit, credit exhaustion and refusal. They require exact unchanged setup state, sanitized terminal feedback and settled replay without additional model allowance. Failure is represented by the runtime input outcome rather than a fabricated empty extraction. |
| Cached retry returns original state before model/stale checks | [Runtime recovery](../../tests/runtime/conversations.test.ts) verifies settled replay without additional model work and post-commit crash recovery without a duplicate review. The [Photon integration](../../tests/integration/photon-execution.test.ts) recovers the original completed reply after a later browser edit and process restart. The new API returns input identity/outcome, not the old complete setup-state object. Current authority is always rechecked; cached results cannot bypass logout/unlink. |
| Stale draft never reaches model or append | **Boundary changed.** New text enters a durable conversation independently of a caller-supplied setup revision. Draft tools must carry the current revision and cannot overwrite newer state. [Host setup integration](../../tests/integration/host-setup.test.ts) and [shared-channel review](../../tests/integration/setup-channel-review.ts) verify stale current-review rejection, unchanged newer drafts and one mutation per input. This is not a claim that accepted conversation text avoids all model work when preferences changed elsewhere. |
| Calendar labels disambiguate duplicates and require write access | Selection now uses explicit calendar IDs, not model-resolved labels. [Calendar selection integration](../../tests/integration/calendar-selection.test.ts) supplies two calendars named `Calendar`, rejects the reader as destination and a later role downgrade, then reads SQL to verify the exact requested conflict and booking IDs. Provider roles remain authoritative. |
| Protected setup text strips credentials but retains scheduling context | The [completed shared-admission change](../../openspec/changes/archive/2026-10-09-protect-conversation-credential-text/proposal.md) restored this dropped behavior for every conversation channel. [SQL text tests](../../supabase/tests/conversation_text.test.sql) cover ordinary English/Korean scheduling prose, query/fragment credentials, bearer values and old linking proofs. Actual runtime and signed Photon integration verify protected model input after restart, with original-input digests preserving changed-secret retry conflicts. |
| Linked calendar lookup uses the authorized host, never service actor ID | **Actor isolation preserved; label lookup retired.** Signed ingress freezes the verified private link. The [two-host integration](../../tests/integration/setup-host-isolation.ts) verifies distinct scopes/sessions, cross-host denial, correct sender delivery and unchanged other-host setup. Private grants can read/draft only the bound host; Calendar choice is made through protected ID-based controls. The former worker actor and natural-language label-selection operation are not current interfaces. |
| Bare confirmation never reaches model or grants settings authority | **Authority preserved; model bypass retired.** The shared-channel integration now submits literal `yes` while a confirmable review exists. Its deterministic model deliberately attempts a draft tool call with `confirmed:true`; actual eve/tool validation rejects it, and the entire draft/review/confirmed state remains unchanged. The existing direct `setup_confirm` RPC attempt under the private runtime grant is also forbidden. Explicit current browser confirmation or the subsequently deployed [deterministic private setup command](14_legacy_onboarding_api_audit.md#retired-onboarding-command-integration-2026-10-10) saves settings. Ordinary model tools remain unable to confirm. This does not claim that bare assent bypasses the model. |
| Partial drafts ask the next missing explicit value without defaults | **Suggestion policy intentionally changed.** [Guide tests](../../lib/contracts/setup-guide.test.ts) and [answer tests](../../lib/contracts/setup-answers.test.ts) preserve explicit values, one next question, dismissal and provenance. The agreed [setup requirements](../../openspec/changes/conversational-host-setup/specs/conversational-host-setup/spec.md) require labeled suggestions before manual entry. Starter defaults are unconfirmed proposals and never satisfy explicit mode/location/travel choices. The old exact duration/focus-block wording and no-defaults policy are not retained. |
| Replies cannot repeat model completion claims in another language | **Structured guidance protected; bounded live narration verified.** The shared-channel fixture rejects the Korean false-completion clarification before drafting; [clarification SQL](../../supabase/tests/setup_clarifications.test.sql) authors English/Korean questions and replaces unknown legacy wording with neutral text without granting authority. This covers the old extraction's `clarification` field. The replacement also displays free-form model replies. Subsequent [live initial-setup acceptance](05_rebuild_evidence.md#live-initial-setup-narration-acceptance--2026-10-10) reviewed six actual English/Korean replies and verified that their draft, scan, readiness and link claims match current synthetic state. This is bounded evidence for initial setup; later-stage narration and complete AC-28 remain open. |

## Limits

The source-level audit is complete, but the last row retains later-stage and full-journey narration obligations. It must not be used to mark full conversational onboarding, the entire legacy behavior migration, live Google consent or actual private-device acceptance complete. Controlled fixture text proves application behavior under those inputs; it is not an evaluation of live model behavior. Fresh verification is recorded in the [evidence ledger](05_rebuild_evidence.md#legacy-setup-conversation-acceptance--2026-10-10).
